# iPhone: App Store 배포 절차

작성 2026-11-22 · 대상은 iPhone 앱(`ios/OnEum.xcodeproj`, 위젯 확장 포함)입니다. Mac용 직접 배포(Developer ID · 공증)는 [RELEASE.md](RELEASE.md) 4 · 5절에 있습니다.

이 문서는 **계정을 가진 사람이 직접 해야 하는 일**과 **저장소에 준비되어 있는 것**을 순서대로 적습니다. 아래 표시가 붙은 단계는 다른 사람이나 도구가 대신할 수 없습니다.

- **[결제]** 돈이 듭니다.
- **[인증]** Apple 계정의 비밀번호와 2단계 인증이 필요합니다.
- **[동의]** 약관이나 계약에 동의해야 합니다.
- **[결정]** 정해야 진행됩니다(13절에 모아 둠).

Apple의 요구 사항은 2026-11-22에 Apple의 공개 문서에서 확인한 것입니다. 금액 · 크기 · 기한은 바뀌므로 제출 직전에 해당 페이지를 다시 보세요. 확인하지 못한 것은 "확인 못 함"으로 적었습니다.

## 1. Apple Developer Program 가입 — [결제] [인증] [동의]

- 연회비는 **99 USD**입니다(Apple의 가입 안내 기준. 지역 통화 금액은 가입 화면에 나오며, 원화 금액은 확인 못 함). 해마다 갱신합니다.
- 개인으로 가입할 때 필요한 것: 2단계 인증이 켜진 Apple 계정, 법적 실명, 성년, 연락 가능한 주소와 전화번호. Apple Developer 앱(자동 갱신 구독) 또는 웹(developer.apple.com/programs/enroll)에서 가입합니다. 결제 뒤 24시간 안에 확인이 오지 않으면 Apple에 문의하라고 되어 있습니다.
- **개인으로 가입하면 App Store의 판매자 이름이 본인의 실명으로 표시됩니다.** 단체 이름으로 내려면 조직으로 가입해야 하고 절차가 더 있습니다. — [결정]
- 이 Mac의 키체인에 있는 조직 팀은 계정 소유자가 약관에 동의하기 전에는 프로파일을 만들 수 없습니다. 그 팀으로 내려면 소유자가 developer.apple.com에서 동의해야 합니다. 개인 팀으로 낼 것이면 관계없습니다.
- 가입 뒤 App Store Connect(appstoreconnect.apple.com)의 **Business**(계약 · 세금 · 은행)에서 계약 상태를 확인합니다. 무료 앱만 낼 때 추가 계약이 필요 없는지는 그 화면에서 확인하세요(확인 못 함). 유료로 팔려면 유료 앱 계약과 은행 · 세금 정보가 필요합니다.
- **EU 디지털서비스법의 판매자(trader) 여부 신고**: EU에 배포하지 않아도 신고해야 한다고 되어 있습니다. 신고하지 않으면 EU의 App Store에서 앱이 내려갑니다. 판매자로 신고하면 연락처가 EU 스토어에 공개되는 것으로 알려져 있으니(확인 못 함) 화면의 안내를 읽고 정하세요. — [결정]

## 2. Xcode에 Apple 계정 로그인 — [인증]

1. Xcode ▸ Settings ▸ Accounts ▸ **+** ▸ Apple Account. 비밀번호와 2단계 인증 코드는 본인이 넣습니다.
2. 팀 ID(영문 · 숫자 10자)를 확인합니다: developer.apple.com ▸ Account ▸ Membership details.
3. 팀 ID는 저장소에 넣지 않고 셸의 환경 변수로만 줍니다.
```bash
export ONEUM_IOS_TEAM=<팀 ID>
```

## 3. 인증서

자동 서명을 쓰므로 직접 만들 것이 없습니다. 2가 되어 있으면 Xcode가 **Apple Development**(아카이브 서명)와 **Apple Distribution**(App Store용 다시 서명) 인증서를 필요할 때 만듭니다. 프로젝트는 두 타깃 모두 `CODE_SIGN_STYLE = Automatic`이고, 스크립트가 `-allowProvisioningUpdates`로 그것을 허용합니다.

키체인에 무엇이 있는지 보려면:
```bash
security find-identity -v -p codesigning
```
(출력에 이름과 팀 ID가 나옵니다. 문서나 이슈에 붙이지 마세요.)

## 4. 앱 식별자와 기기 — [결정]

| 무엇 | 값 | 어디서 정해지나 |
|---|---|---|
| 앱 | `app.oneum.OnEum` | `ONEUM_IOS_BUNDLE_ID`(기본값) |
| 위젯 확장 | `app.oneum.OnEum.widget` | 앱 식별자 + `.widget`(프로젝트) |
| 앱과 위젯이 함께 쓰는 키체인 그룹 | `<팀 접두어>.app.oneum.OnEum.nowplaying` | `ios/OnEum.entitlements`, `ios/Widget/OnEumWidget.entitlements` |

- 식별자 등록은 자동 서명이 합니다. **번들 ID는 전 세계에서 하나뿐**이라, 다른 사람이 `app.oneum.OnEum`을 이미 등록했으면 실패합니다. 그때는 본인 소유의 도메인을 뒤집은 것 등으로 바꿔 `ONEUM_IOS_BUNDLE_ID`에 줍니다. **App Store Connect에 한 번 올린 뒤에는 번들 ID를 바꿀 수 없습니다.**
- 지금 본인 iPhone에 있는 앱은 개인 팀용 식별자(끝에 팀 ID가 붙은 것)라서 App Store용과 **다른 앱**입니다. 둘이 따로 설치되고 보관함과 설정은 넘어가지 않습니다. 옮기려면 설정의 보관함 데이터 내보내기 · 가져오기를 씁니다.
- 켜야 하는 기능(Capabilities)은 없습니다. 키체인 그룹은 팀의 접두어만 있으면 되고 App Group을 쓰지 않습니다. 스크립트가 서명된 앱과 위젯이 같은 그룹에 서명되었는지 검사합니다.
- **기기 등록**: 자동 서명의 아카이브는 개발용 프로파일로 서명되는데, 팀에 등록된 기기가 하나도 없으면 Xcode가 그 프로파일을 만들지 못할 수 있습니다(유료 팀으로 해 본 적이 없어 확인 못 함). 그 오류가 나오면 iPhone을 연결하고 유료 팀으로 한 번 설치합니다.
```bash
scripts/ios-device.sh
```

## 5. App Store Connect에 앱 만들기 — [인증] [결정]

appstoreconnect.apple.com ▸ Apps ▸ **+** ▸ New App.

- 플랫폼 iOS, 번들 ID는 4에서 등록된 것, SKU는 내부용 문자열(아무것이나, 공개되지 않음).
- **이름**은 2~30자이고 App Store 전체에서 하나뿐입니다. "OnEum"을 쓸 수 있는지는 만들어 봐야 압니다. — [결정]
- 기본 언어를 고릅니다(한국어 또는 영어). 앱은 두 언어를 지원하므로 스토어 정보도 두 언어로 넣을 수 있습니다.

번들 ID가 목록에 나오지 않으면 4의 등록이 아직 안 된 것입니다. 서명된 아카이브를 한 번 만들면(6절) 등록됩니다.

## 6. 아카이브 · 검사 · 업로드

`main`의 커밋된 상태에서 합니다. 버전은 `Cargo.toml`의 `version`, 빌드 번호는 커밋 수입니다.

계정 없이 미리 해 볼 수 있는 것(서명 없는 아카이브와 검사):
```bash
scripts/ios-archive.sh --unsigned
```
서명된 아카이브와 `.ipa`(`dist/ios/OnEum-<버전>-<빌드>.ipa`):
```bash
scripts/ios-archive.sh
```
App Store Connect로 바로 보내기:
```bash
scripts/ios-archive.sh --upload
```
Xcode가 만든 아카이브나 다른 곳의 `.ipa`를 검사만 하기:
```bash
scripts/ios-archive.sh --check <.xcarchive 또는 .ipa>
```

스크립트가 검사하는 것(하나라도 틀리면 실패):
- 앱과 위젯 확장의 식별자(확장 = 앱 + `.widget`), 버전과 빌드 번호가 서로 같고 `Cargo.toml` · 커밋 수와 같은지, App Store Connect가 받는 형식(숫자와 마침표)인지.
- 앱과 위젯이 같은 키체인 그룹 이름을 전달받았는지, 서명되어 있으면 둘 다 그 그룹에 서명되었는지.
- 개인정보 매니페스트, 두 언어의 권한 안내문, 샘플 음악, 아이콘 이름, 로컬 네트워크 안내문, 암호화 신고 키가 들어 있는지.
- 실행 파일이 arm64 하나인지, 검증 채널(`automation` 기능)이 든 빌드가 아닌지.
- 아카이브(또는 `.ipa`)의 어느 파일에도 이 Mac의 경로(`/Users/…`)가 없는지.
- `.ipa`는 서명과 프로비저닝 프로파일이 있고 개발용 서명(`get-task-allow`)이 아닌지.

알아 둘 것:
- **빌드 번호는 한 버전에서 한 번만 쓸 수 있습니다.** 같은 커밋을 다시 올리려면 더 큰 번호를 줍니다: `ONEUM_IOS_BUILD=<번호>`.
- 팀 ID가 든 `ExportOptions.plist`는 `target/xcode/`에 만들어지고 저장소에 들어가지 않습니다.
- 올리는 다른 방법: Xcode에서 `target/xcode/OnEum.xcarchive`를 열어 Organizer ▸ Distribute App, 또는 Mac App Store의 Transporter 앱에 `.ipa`를 끌어다 놓기.
- 업로드 조건(2026-04-28부터 Xcode 26 이상과 iOS 26 SDK 이상, 2026-09-09부터 최소 iOS 13 이상)은 충족합니다: Xcode 27.2, iOS 27.2 SDK, 최소 iOS 16.0.
- 디버그 기호 파일(dSYM)은 만들지 않습니다(Rust 실행 파일은 디버그 정보를 뺀 것). 업로드 때 기호가 없다는 경고가 나올 수 있고, 그 경우 App Store Connect의 충돌 보고서에 함수 이름이 덜 나옵니다.
- 올린 뒤 Apple이 자동 검사 결과를 e-mail로 보냅니다(`ITMS-…`). 무엇이 올지는 올려 봐야 압니다.

## 7. TestFlight

- 업로드한 빌드는 처리(몇 분) 뒤 App Store Connect ▸ TestFlight에 나옵니다.
- **내부 테스터**(App Store Connect 사용자, 100명까지)는 심사 없이 바로 설치합니다. **외부 테스터**(10,000명까지)는 그룹의 첫 빌드가 베타 심사를 거칩니다. 빌드는 90일 동안 쓸 수 있습니다.
- 본인 iPhone에 TestFlight 앱으로 설치해, 시뮬레이터로 확인하지 못한 것을 여기서 봅니다([TESTING.md](TESTING.md) "iPhone"의 실제 기기 항목): 홈 화면 · 잠금 화면 위젯에 곡이 나오는지(배포 서명에서의 키체인 그룹), 로컬 네트워크 권한 창의 문구(한국어 · 영어), 연결한 폴더, 전화가 올 때의 끊김, 이어폰 분리, 가로 화면.

### 스크린샷
- 한 크기에 1~10장, `.png` 또는 `.jpg`, 투명도 없음.
- **큰 화면(Dynamic Island, large)** 크기로 준비합니다: 세로 1320×2868, 1290×2796, 1260×2736 중 하나(가로는 뒤집은 값). 이것이 없으면 Face ID 큰 화면(1284×2778 또는 1242×2688)이 필수입니다. 다른 iPhone 크기는 큰 것에서 줄여 씁니다.
- iPad 칸은 "앱이 iPad에서 실행되면 필수"라고 되어 있습니다. OnEum은 iPhone 전용(기기군 1)이라 요구되지 않을 것으로 보지만 **확인 못 함**: App Store Connect의 화면에서 확인하세요.
- **iPhone Duo**(접는 iPhone): 2027년 4월부터 iOS 27.1 SDK 이상으로 만든 앱은 Duo 스크린샷이 필수가 된다고 되어 있습니다(바깥 1398×2034, 안쪽 2007×2853). OnEum은 iOS 27.2 SDK로 빌드하므로 해당합니다. Duo에서의 화면은 **확인한 적이 없습니다**.
- 찍는 법: `scripts/dev/appstore-shots.sh`가 큰 화면 시뮬레이터에서 두 언어로 일곱 장씩 찍어 `dist/appstore/`에 둡니다(1320×2868, 소리 없이). 어떤 화면인지와 알아 둘 것은 [APP_STORE_LISTING.md](APP_STORE_LISTING.md) "스크린샷". 보관함은 지어낸 음악가의 것(`python3 scripts/dev/gen-demo-library.py <폴더>`)을 씁니다. **실제 음악가의 이름과 표지를 스크린샷에 넣지 마세요**(저작권, 심사).

## 9. 앱 개인정보 — [결정]

App Store Connect ▸ App Privacy에서 무엇을 수집하는지 답합니다. Apple의 정의: "수집"은 데이터를 기기 밖으로 보내, 본인이나 제3자가 그 요청을 처리하는 데 필요한 시간보다 오래 접근할 수 있게 하는 것입니다. 기기 안에서만 처리하는 데이터는 수집이 아닙니다.

OnEum의 사실:
- 계정 · 자체 서버 · 분석 · 광고 · 추적이 없습니다. 보관함과 설정은 기기에 있습니다. 개인정보 매니페스트(`ios/PrivacyInfo.xcprivacy`)도 추적 없음 · 수집 없음으로 되어 있습니다.
- 사용자가 추가한 미디어 서버(DLNA)와 네트워크 폴더(WebDAV)에는 그 사용자의 서버로 접속합니다. 비밀번호는 기기의 키체인에 둡니다.
- **인터넷 가사**(기본은 꺼짐)를 켜면, 가사를 보는 곡의 제목 · 아티스트 · 앨범 · 길이가 LRCLIB(lrclib.net)로 갑니다. 다른 것은 가지 않습니다. LRCLIB가 그 요청을 얼마나 보관하는지는 OnEum이 정하지 못합니다.

정할 것: "데이터를 수집하지 않음"으로 답할지. 위 정의로는 그렇게 답할 근거가 있지만, 인터넷 가사 때문에 달리 볼 여지가 있습니다. 어느 쪽이든 **개인정보 처리방침에는 인터넷 가사에서 무엇이 어디로 가는지 적으세요.**

처리방침 URL은 필수입니다. 홈페이지에 페이지를 만들어 두었습니다(초안, 2026-11-22): `site/privacy.html`(한국어)과 `site/en/privacy.html`(영어). 네 플랫폼 모두에 해당하는 내용이고, 위의 사실에 더해 기기에 남는 것 · 지우는 법 · 권한 · 스토어의 통계 · 문의 방법을 적었습니다. **본인의 이름으로 공개되는 글이니 제출 전에 읽고 고치세요.** `main`을 push해 홈페이지가 게시되면 주소는 `https://ywjung.github.io/oneum/privacy.html`과 `https://ywjung.github.io/oneum/en/privacy.html`입니다(게시된 것을 확인한 적은 없음). 인터넷 가사를 iPhone판에서 빼거나 앱이 접속하는 곳이 바뀌면 이 페이지도 함께 고칩니다.

## 10. 수출 규정(암호화) — [결정]

- 지금 `ios/Info.plist`는 `ITSAppUsesNonExemptEncryption = false`입니다. 이 키가 있으면 제출할 때마다 암호화 질문이 나오지 않습니다.
- Apple의 설명: 앱(링크한 라이브러리 포함)이 암호화를 쓰지 않거나, **문서 제출이 면제되는 형태만** 쓰면 NO입니다. 운영체제의 암호화(URLSession의 HTTPS 등)는 면제입니다.
- OnEum의 사실: HTTPS(WebDAV 폴더, 인터넷 가사)에 운영체제의 것이 아닌 표준 TLS 구현(rustls · ring)을 앱에 담아 씁니다. Apple의 질문지에서는 "업계 표준 알고리즘이지만 Apple 운영체제가 제공하는 것이 아님"에 해당하고, 그 답에 요구되는 문서는 **프랑스 암호화 신고서**이며 "프랑스의 App Store에 배포할 때만 필요"하다고 되어 있습니다. 프랑스 밖에서 요구되는 문서가 있는지는 확인 못 함.

선택지:
1. **프랑스를 배포 국가에서 빼고** 지금 값을 둡니다. 가장 간단합니다.
2. 프랑스에도 내려면 프랑스 당국에 신고하고, 그 서류를 App Store Connect에 올린 뒤 Apple이 주는 코드를 `ITSEncryptionExportComplianceCode`로 넣고 위 키를 `true`로 바꿉니다.
3. 키를 빼고 제출할 때마다 질문에 직접 답합니다.

이것은 법률 판단이 들어가는 일이라 여기서 정해 드릴 수 없습니다. Apple의 "Complying with Encryption Export Regulations"와 App Store Connect 도움말의 "Export compliance documentation for encryption"을 직접 읽고 정하세요.

## 14. 확인한 것과 확인하지 못한 것 (2026-11-22)

확인한 것(이 Mac, Xcode 27.2, 계정 없이):
- `scripts/ios-archive.sh --unsigned`가 아카이브를 만들고 검사를 통과: 앱과 위젯 확장이 0.1.0 · 같은 빌드 번호, 식별자 `app.oneum.OnEum` · `app.oneum.OnEum.widget`, 두 곳의 키체인 그룹 이름이 같음, 개인정보 매니페스트 · 두 언어의 안내문 · 샘플 음악 · 아이콘이 들어 있음, arm64.
- **아카이브에는 이 Mac의 경로가 없음**: 앱(Rust)과 위젯(Swift) 실행 파일을 포함해 아카이브의 모든 파일을 바이트 단위로 찾아 `/Users/`가 0건. 위젯 실행 파일은 `build` 동작(`scripts/ios-device.sh`)으로 만들면 기호 표에 소스 폴더와 목적 파일의 경로가 남지만(디버그 지도 항목 세 개), `archive` 동작은 설치 단계에서 기호를 벗겨 내므로 남지 않습니다. App Store에는 아카이브만 올라가고, 스크립트가 매번 검사합니다. (`strings -a`로는 이 경로가 보이지 않습니다: 섹션만 읽기 때문입니다. 검사는 `grep -a`로 합니다.)
