계획과 달라진 것:
- **씬 생명주기**가 필요했다(계획에 없던 것). iOS 27이 씬 없는 앱을 시작할 때 종료해서, 씬 델리게이트를 앱이 만들어 winit의 창을 씬에 넣는다.

- **화면 모드**: winit이 iOS에서 시스템의 밝은/어두운 설정을 알려 주지 않아 직접 읽어 넘긴다.

## 1. 결론

- **할 수 있다고 본다.** 재생·보관함·저장 코드(약 3.1만 줄)는 화면과 분리되어 있고, 지금 쓰는 버전의 winit·cpal·eframe·wgpu에 iOS용 코드가 들어 있다(확인함).
- **화면은 egui를 유지하고 폰 전용 배치를 새로 만드는 쪽을 권한다.** 다만 한글 입력 등 네 가지가 0단계에서 통과해야 한다. 통과하지 못하면 SwiftUI 화면 + Rust 코어로 바꾼다(2절).
- **새로 필요한 것은 주로 세 가지다.** iPhone용 플랫폼 모듈, 폰 화면, 파일 접근 방식(샌드박스).
- **기간은 0단계 뒤에 추정한다.** 지금 숫자를 적으면 근거 없는 값이 된다.
- **시작 전에 정해 주실 것이 다섯 가지 있다**(7절). 그중 Rust iOS 타깃 설치는 다운로드라서 허락이 필요하다.

## 2. 화면 방식 (결정 필요)

| | A. egui 유지 + 폰 배치 (권고) | B. SwiftUI 화면 + Rust 코어 |
|---|---|---|
| 새로 쓰는 것 | 폰 배치와 터치 동작 | 화면 전체, Rust↔Swift 연결 계층 |
| 다시 쓰는 것 | 테마·아이콘·위젯·스펙트럼·미터·이퀄라이저 그리기(3,831줄), 자동 조작 훅 | 코어만 |
| 언어 | Rust 하나 | Rust + Swift |
| 약점 | 스크롤·제스처가 iOS 기본과 다른 느낌, 한글 입력·VoiceOver가 확인 필요 | 작업량이 가장 큼, 테스트 체계를 따로 만들어야 함 |

A를 권하는 이유는 현재 UI 14,545줄 가운데 그리기 코드는 그대로 쓸 수 있고, 지금의 스모크 테스트 방식(스크립트로 egui에 입력을 넣는 `ONEUM_SCRIPT`)을 시뮬레이터에서도 쓸 수 있기 때문이다.
나머지 약 1.07만 줄(사이드바, 표, 메뉴 막대, 설정 창)은 데스크톱 배치라서 어느 쪽이든 폰용으로 다시 만들어야 한다.

A를 계속할지는 0단계의 다음 네 가지로 정한다. 하나라도 고칠 수 없으면 B로 간다.

1. 검색창에 한글이 조합되어 들어간다. winit 0.30.13의 iOS 뷰는 `insertText`와 `deleteBackward`만 받고 조합 중 글자(marked text)를 다루지 않는다(확인함). 한글 자판이 이 방식으로 동작하는지는 확인 필요.
2. 한글 글자가 보인다. 지금은 macOS 경로의 시스템 글꼴과 eframe의 시스템 글꼴 대체에 기대고 있다. iOS에서 되는지 확인 필요. 안 되면 한글 글꼴을 앱에 넣는다(용량 증가).
3. 긴 목록의 터치 스크롤과 탭이 쓸 만하다.
4. 백그라운드로 갔다 돌아와도 화면이 다시 그려지고 죽지 않는다.

## 4. iPhone이 요구하는 것

### 4.1 음악 파일과 경로

iPhone 앱은 자기 보관 공간 밖을 마음대로 읽지 못한다. 두 단계로 간다.

- **1차: 앱의 문서 폴더.** 파일 앱의 "나의 iPhone › OnEum"과 Mac의 Finder(케이블 연결)에 보이게 하고, 사용자가 음악 폴더를 거기로 복사한다. 앱은 이 폴더를 보관함 폴더로 자동 등록한다.
- **나중: 바깥 폴더.** iCloud Drive나 USB 저장 장치의 폴더를 문서 선택기로 고르고, 다음 실행에도 열 수 있게 접근 권한(보안 범위 북마크)을 저장한다.

**경로 문제가 하나 있다.** 지금 DB는 폴더와 곡의 경로를 절대 경로로 저장한다(`roots.path`, `tracks.path`, 확인함). iPhone에서는 앱을 업데이트하거나 복원하면 보관 공간의 경로가 바뀔 수 있다. 그대로 두면 모든 곡이 "파일 없음"이 된다.
대응은 저장할 때 보관 공간 기준의 상대 경로로 바꾸고 읽을 때 현재 위치를 붙이는 것이다. DB의 경로는 `src/storage/db.rs`의 변환 함수 두 개(`platform::path_to_bytes`·`path_from_bytes`를 부른다)만 지나므로(확인함) 거기서 처리한다. CUE 시트 기록(JSON의 문자열 경로)과 설정 파일의 고정 폴더처럼 이 함수를 지나지 않는 곳은 찾아서 같은 변환을 거치게 한다.
이 부분은 "보관함을 만든 뒤 위치를 옮겨 다시 열어도 그대로"라는 테스트로 Mac에서 검증할 수 있다.

Apple Music 보관함의 곡은 대상이 아니다(파일로 읽을 수 없다).

### 4.2 소리

- cpal의 iOS 호스트는 오디오 세션의 끊김과 경로 변경을 감시하고 끊김 뒤 스트림을 되살린다. 세션의 종류(재생용)를 정하는 코드는 없다(확인함). 앱이 직접 정하고 켠다.
- **백그라운드 재생:** 앱 설정에 오디오 백그라운드 모드를 넣는다. 재생 중에는 화면이 꺼져도 프로세스가 살아 있다.
- **끊김(전화, 알람, Siri):** 시작되면 일시정지 상태로 맞추고, 끝났을 때 시스템이 "다시 재생해도 됨"이라고 하면 이어서 재생한다.
- **이어폰 분리:** 일시정지한다. 데스크톱의 "장치가 빠지면 일시정지"와 같은 동작이다.
- **출력 장치 고르기:** iOS는 시스템이 경로를 정한다. 설정의 장치 목록은 없애고, AirPlay·블루투스 선택은 시스템 버튼으로 나중에 넣는다.
- **곡의 샘플레이트에 맞추기:** 내장 스피커에서는 의미가 없다. USB DAC에서는 세션에 원하는 샘플레이트를 요청할 수 있지만 시스템이 정한다. 실제 기기와 DAC가 있어야 확인할 수 있어 뒤 단계로 미룬다. 그때까지는 지금의 리샘플러가 맞춘다.
- **독점 모드:** iOS에 없다. 옵션을 숨긴다.

### 4.3 잠금 화면과 제어 센터

곡 정보·표지·재생 위치와 재생/일시정지/다음/이전/탐색 명령을 연결한다. macOS와 같은 프레임워크라 코드를 나눠 쓴다. 곡 정보 갱신은 화면 그리기가 아니라 앱 코어(`src/app/mod.rs`의 `refresh_now_playing`)가 메인 스레드로 넘겨서 한다(확인함). 그래서 화면이 멈춘 백그라운드에서도 바뀔 것으로 보지만, iPhone에서 실제로 그런지는 2단계에서 확인한다.

### 4.4 시작과 종료

- winit의 iOS 실행 루프는 돌아오지 않는다. `main.rs`에서 창이 닫힌 뒤에 하던 정리(`core.shutdown()`)는 실행되지 않는다.
- iOS는 앱을 알리지 않고 종료할 수 있다. 백그라운드로 갈 때 설정을 저장한다. 대기열·위치·음량은 재생 스레드가 이미 저장한다(확인함).
- 스캔 도중 멈췄다가 종료되어도 다음 스캔에서 회복되어야 한다. 이 성질은 무작위 모델 테스트가 이미 다루고 있다.
- 폴더 감시 대신 앱이 앞으로 올 때와 파일을 받은 뒤에 다시 스캔한다. 감시 없는 폴더를 주기적으로 다시 읽는 경로는 이미 있다.
  (2026-11-15: 그 경로를 iPhone에서는 30초마다 돌린다. 감시기는 iOS에서 파일마다 핸들을 열어 두므로 쓰지 않는다.)

### 4.5 메모리와 배터리

- "메모리 재생"은 지금 설치된 메모리의 1/8까지(최대 1.5 GiB) 파일을 올린다(`MEMORY_SHARE`, 확인함). iPhone은 앱 한도가 더 낮으므로 상한을 따로 두고, 메모리 경고가 오면 놓아 준다.
- 음량 분석과 파일 검사는 CPU를 오래 쓴다. 1차에서는 자동으로 돌리지 않고 사용자가 시작할 때만 돌린다.

### 4.6 빠지거나 달라지는 것

- 없음: 메뉴 막대, 창 크기 복원, Finder에서 보기, 독점 모드, 다른 창에서 끌어다 놓기. (계획할 때는 장치별 샘플레이트 전환과 Apple Music 보관함 가져오기도 없는 것으로 적었으나 2026-11-15에 넣었다.)
- 달라짐: 우클릭 메뉴는 길게 누르기, 키보드 단축키는 화면 버튼, 플레이리스트 가져오기·내보내기는 문서 선택기와 공유 시트.

## 5. 단계

각 단계는 끝날 때마다 `scripts/check.sh`(지금 552개 테스트)와 macOS 스모크 테스트(114개)가 그대로 통과해야 한다. 작업은 새 브랜치(`feature/ios`)에서 한다.

| 단계 | 목표 | 하는 일 | 통과 기준 |
|---|---|---|---|
| 0 기술 검증 | A안이 되는지 확인 | Rust iOS 타깃 설치. 버릴 브랜치에서 최소 앱(egui 목록·입력창, cpal 출력, SQLite, 디코딩 한 번)을 시뮬레이터에 올림 | 2절의 네 가지 + 소리가 나감(미터 값으로 확인) + 화면 잠금 중에도 재생 + VoiceOver가 위젯을 읽음. 결과를 `docs/adr/0002`에 기록 |
| 1 코어 빌드 | 화면 없이 iOS로 컴파일 | `Cargo.toml` 대상 분리, iPhone 플랫폼 모듈(중립 대역 위주), 경로 상대화 | iOS 대상 clippy가 `check.sh`에 들어가 통과. 경로 이동 테스트 통과. 시뮬레이터에서 코어 테스트 실행 |
| 2 소리 내기 | 폰에서 한 곡을 끝까지 | 시뮬레이터용 앱 묶음 스크립트, 오디오 세션, 문서 폴더 보관함, 스캔, 임시 목록에서 눌러 재생, 잠금 화면 제어 | 문서 폴더에 넣은 시험 음원이 스캔되어 재생됨. 잠금 화면에서 일시정지·다음 곡. 다시 실행하면 대기열·위치 복원 |
| 3 폰 화면 | 일상 사용 | 아래 탭, 목록(곡·앨범·아티스트·폴더·플레이리스트), 검색, 지금 재생, 대기열, 설정 일부. 스크립트 조작 훅을 시뮬레이터에 연결 | 시뮬레이터 스모크 테스트(핵심 흐름)가 통과. 화면 캡처로 배치 확인 |
| 4 iPhone 동작 | 끊김과 생명주기 | 끊김·이어폰 분리, 백그라운드 저장, 메모리 경고, 앞으로 올 때 다시 스캔, 문서 선택기, "OnEum으로 열기" | 시뮬레이터에서 할 수 있는 것은 자동으로, 나머지는 실제 기기 점검표로 |
| 5 확장 | 데스크톱 기능 옮기기 | 바깥 폴더, 이퀄라이저·헤드폰 보정 화면, 가사, 통계, 파일 검사, USB DAC, iPad 배치 | 기능마다 따로 정함 |
| 6 기기와 배포 | 실제 iPhone에 설치 | Xcode 프로젝트, 서명, 아이콘·시작 화면, 고지 문서, (선택) TestFlight·App Store | 실제 기기 점검표 통과 |

1차 목표는 0~4단계까지다. 5단계는 그 뒤에 필요한 것만 고른다.

## 6. 검증과 위험

### 검증 방법

- **코어:** 지금의 552개 테스트는 대부분 운영체제와 무관하므로 Mac에서 계속 돈다. iOS 대상 clippy를 `check.sh`에 세 번째 대상으로 넣어 빌드가 깨지지 않게 한다. 시뮬레이터용 테스트 바이너리는 `simctl`로 실행한다(확인 필요).
- **화면:** 시뮬레이터의 앱 보관 공간은 Mac에서 접근할 수 있으므로 지금의 스크립트 파일 방식이 그대로 통할 것으로 본다(확인 필요). 이 환경의 시뮬레이터 조작 도구로 화면 캡처와 탭도 할 수 있다.
- **소리:** 지금처럼 앱 음량 0에서 미터 값으로 확인한다.

### 시뮬레이터로 확인할 수 없는 것

실제 전화가 올 때의 끊김, 이어폰·블루투스 분리, USB DAC의 샘플레이트, 실제 메모리 한도에서의 종료, 배터리 사용량, 케이블로 파일을 넣는 과정. 이들은 실제 기기가 있어야 하고, 그때까지는 "미확인"으로 적는다.

### 위험

| 위험 | 대응 |
|---|---|
| 한글 조합 입력이 안 됨 | 0단계에서 확인. 안 되면 입력창만 iOS 입력란을 겹쳐 쓰는 다리(macOS의 응답 체인 브리지와 같은 방식). 그것도 안 되면 B안 |
| 한글 글꼴이 안 나옴 | 0단계에서 확인. 한글 글꼴을 앱에 포함 |
| 보관 공간 경로 변경으로 보관함이 깨짐 | 상대 경로 저장 + 위치 이동 테스트(1단계) |
| 백그라운드에서 그리기 시도로 종료 | 0단계에서 20회 왕복 확인. 백그라운드에서는 다시 그리기 요청을 막음 |
| egui의 터치 느낌이 부족 | 0단계에서 직접 써 보고 판단. 기준 미달이면 B안 |
| 큰 파일(DSD)에서 메모리 초과 | iOS용 상한, 메모리 경고 처리(4단계) |

| 실제 기기 없이 끝냄 | 문서에 미확인 항목으로 남기고 "완료"라고 쓰지 않음 |

## 7. 시작 전에 정해 주실 것

1. **Rust iOS 타깃 설치.** `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`은 다운로드다. 허락하시면 0단계에서 실행한다.
2. **실제 iPhone으로 시험할지.** 한다면 Apple ID가 필요하다. 무료 계정은 설치한 앱이 7일 뒤 만료되고, 유료 개발자 계정은 TestFlight와 App Store까지 된다.
3. **배포 범위.** 본인 기기만 / TestFlight / App Store. App Store까지면 6단계에 심사 준비가 더해진다.
4. **1차 범위.** 5절의 0~4단계(보관함·검색·재생·대기열·플레이리스트·잠금 화면)로 충분한지, 이퀄라이저나 가사가 처음부터 필요한지.
5. **최소 iOS 버전.** 이 Mac에는 iOS 26.0과 27.0 시뮬레이터가 있다. 의존성이 요구하는 최저 버전은 0단계에서 확인한다.
