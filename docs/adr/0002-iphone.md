# ADR 0002 — iPhone: egui 유지, 폰 전용 화면, 플랫폼 모듈 추가

- 상태: 확정 (2026-11-14)
- 검증 환경: iOS 27.0 시뮬레이터(iPhone 17, Xcode 27.2), Apple M4, Rust 1.99.1, eframe/egui 0.37.0, winit 0.30.13, cpal 0.18.2
- 실제 iPhone 18 Pro(iOS 27.2.1)에는 설치해서 실행되는 것까지 확인했다(시작, 음악 폴더 등록, Metal로 그리기 — 기기의 앱 로그). 아래 표의 결과는 모두 시뮬레이터에서 본 것이다.
  폰 화면을 다듬은 빌드를 덮어 설치했을 때(같은 날 밤) 기기의 로그에서 보관 공간 경로가 바뀌고 보관함이 따라간 것(경로 5개, 4곡 그대로)과 그 전 사용 중에 원격 명령 `Pause`가 도착한 것을 봤다.

## 배경
macOS·Windows용 앱을 iPhone에서도 동작하게 한다. 화면을 egui로 유지할지 SwiftUI로 새로 만들지는
계획([IOS_PLAN.md](../IOS_PLAN.md))에서 네 가지 확인에 맡겼다: 한글 조합 입력, 한글 글꼴, 터치 스크롤, 백그라운드 왕복.

## 검증 결과
| 항목 | 방법 | 결과 |
|---|---|---|
| 빌드 | `aarch64-apple-ios-sim`, `aarch64-apple-ios`로 전체 의존성과 앱 | 둘 다 컴파일·링크됨. 기기용은 Xcode 프로젝트로 릴리스 빌드까지(서명 제외) |
| 한글 조합 입력 | 검색 칸을 눌러 화면 자판의 ㅅㅏㄹㅏㅇ을 실제 터치로 입력 | `사랑`으로 조합되고 검색 결과가 나옴 |
| 한글 글꼴 | 한글 곡 제목·메뉴 표시 | 표시됨(eframe `system_fonts`). Latin은 `/System/Library/Fonts/Core/SFUI.ttf` |
| 터치 | 실제 탭과 스와이프 | 탭으로 이동·재생, 스와이프로 목록 스크롤 |
| 재생 | 음량 0에서 재생 상태·위치·언더런 수 확인 | 재생되고 다음 곡으로 넘어감, 언더런 0 |
| 백그라운드 재생 | 재생 중 홈으로 나가 80초 뒤 복귀 | 그사이 세 곡이 넘어가 있었고 복귀 후 정상 |
| 파일 가져오기 | 문서 선택기에서 "나의 iPhone"의 파일을 골라 열기 | `Documents/Imported`로 옮겨지고 스캔되어 21곡 |
| 보관 공간 이동 | 재설치로 컨테이너 경로가 바뀌게 함 | 경로 21개를 옮기고 새로 읽은 파일 0 |
| 화면 모드 | 시뮬레이터를 밝게/어둡게 전환 | 앱과 상태 표시줄이 따라감 |

## 발견한 문제와 대응
1. **iOS 27은 씬 생명주기를 쓰지 않는 앱을 시작할 때 종료한다.** winit 0.30은 씬 없이 창을 만든다.
   → 씬 델리게이트를 앱이 만들고(`platform/ios/scene.rs`, Info.plist에 이름 등록) 씬이 연결되면 winit의 창을 그 씬에 넣는다.
   파일 열기(`scene:openURLContexts:`)와 백그라운드 진입·복귀도 이 델리게이트로 받는다.
2. **화면이 세로로 12% 늘어나고 아래가 잘렸다.** winit은 창 크기를 안전 영역만큼으로 알려 주고 eframe은 그 크기로 그리는 표면을 만드는데,
   egui는 화면 전체 크기로 배치한다. → winit의 창 클래스에 `safeAreaInsets`가 0을 돌려주는 메서드를 런타임에 추가해 두 크기를 화면 전체로 맞추고,
   실제 여백은 `UIWindow`의 원래 구현에서 읽어 egui에 직접 넘긴다(`raw_input_hook`).
3. **`UISceneConnectionOptions.URLContexts`가 nil일 수 있다.** 바인딩은 nil이 아니라고 선언해 패닉이 났다. → 직접 호출해 `Option`으로 받는다.
4. **이어폰이 빠지면 cpal은 스트림 무효화로 알리고 엔진은 새 경로(스피커)로 다시 연다.** 폰에서는 스피커로 소리가 나면 안 된다.
   → 경로 변경 알림을 앱이 따로 받아 일시정지한다. 전화 등 끊김도 일시정지로 반영하고, 시스템이 재개를 허락하고 우리가 멈춘 경우에만 다시 재생한다(`platform/ios/sound.rs`).
5. **설치할 때마다 컨테이너 경로가 바뀐다**(실제 기기의 업데이트·복원과 같다). DB의 경로는 절대 경로다.
   → 시작할 때 지난번 컨테이너 경로와 다르면 그 아래의 경로를 한 트랜잭션으로 새 위치로 옮긴다(`Db::follow_home`): 음악 폴더, 곡, CUE 시트 기록.
6. **winit은 iOS에서 시스템의 밝은/어두운 모드를 알려 주지 않는다.** → 씬의 값을 읽어 egui에 넘기고, 앱에서 고른 모드는 창에 지정해 상태 표시줄과 시스템 시트가 따르게 한다.
7. **`MPMediaItemArtwork`의 초기화 메서드가 바인딩에 macOS용만 있다.** → iOS에서는 같은 메서드를 직접 호출한다.

폰 화면을 다듬으며 나온 것(2026-11-14, 시뮬레이터에서 측정·확인):

8. **앨범 격자가 가만히 있어도 표지를 초당 약 120장 다시 읽어 올렸다.** 격자 칸(3배율에서 한 변 약 520픽셀)에 256픽셀 표지는 흐려서 큰 표지를 썼는데,
   큰 표지는 4장만 남기게 되어 있어 화면에 보이는 것을 버리고 다시 읽기를 프레임마다 되풀이했다.
   → 표지 크기를 셋(256·400·640픽셀, 각각 320·48·4장 유지)으로 나누고, 이번 프레임이나 바로 앞 프레임에 쓰인 표지는 한도를 넘어도 버리지 않는다(`ui/art.rs`의 `to_evict`, 단위 테스트).
9. **끌기만 감지하는 영역이 버튼 위에 있으면 그 버튼은 눌리지 않는다**(egui의 판정: 맨 위가 끌기 전용이면 그 아래의 탭을 넘기지 않음).
   → 플레이어를 끌어내리는 영역은 버튼보다 먼저(아래에) 두고, 왼쪽 끝에서 뒤로 가는 스와이프는 영역을 두지 않고 포인터의 움직임을 직접 읽는다.
10. **egui의 `Area`·`Modal`·레이어 페인터는 안전 영역 안으로 제한된다.** 시트의 배경과 대화상자의 어두운 배경이 상태 표시줄과 홈 표시줄 자리에서 끊겨 밝은 띠가 남았다.
    → 시트는 제한을 끄고(`constrain(false)`) 화면 아래 밖에서 올라오게 했고, 대화상자는 안전 영역 밖의 띠를 따로 칠한다.
11. **통계 화면이 제목만 나오고 내용이 보이지 않았다.** 스크롤 영역 안에 스크롤 영역을 넣어 안쪽 영역의 높이가 한 줄이 됐다. → 한 겹으로 하고, 폰에서는 목록을 한 줄로 세운다.

## 결정
- egui/eframe을 유지한다. 한글 입력·글꼴·터치·백그라운드 왕복이 모두 통과했다.
- 폰 화면은 `ui::phone`에 따로 둔다(아래 탭, 탭마다 화면 스택, 미니 플레이어, 전체 화면 플레이어, 아래에서 올라오는 시트).
  같은 스냅샷과 같은 동작(`Action`)을 쓰고, 설정 본문·사용 안내·통계·테마·아이콘은 데스크톱 것을 그대로 쓴다.
  모든 플랫폼에서 컴파일되며 `ONEUM_PHONE=1`로 Mac의 창에서도 볼 수 있다.
- 음악은 앱의 Documents 폴더에 둔다(파일 앱의 "나의 iPhone › OnEum", Finder의 파일 공유). 다른 곳의 음악은 문서 선택기로 골라 그 폴더로 복사한다.
  바깥 폴더를 제자리에서 읽는 방식(보안 범위 북마크)은 넣지 않았다.
- 플레이어의 표지 자리에 **VU 미터·스펙트럼·가사**를 보여 준다(오른쪽 위 버튼으로 고름). 바늘과 스펙트럼은 데스크톱의 그리기 코드(`ui/meter.rs`, `ui/spectrum.rs`)를 그대로 쓴다.
  미터가 보일 때만 매 프레임 그리고, 그 밖에는 재생 중 초당 4번(재생 위치 표시), 멈춰 있으면 그리지 않는다.
- 화면 전환(밀려 들어옴), 왼쪽 끝에서 뒤로 가는 스와이프, 플레이어·시트를 아래로 끌어 닫기는 `ui/phone.rs`가 직접 그린다. 설정 줄·이퀄라이저·대화상자·사용 안내는 터치일 때 크기와 배치가 달라진다(`theme::touch`).
- macOS판의 기능은 폰 화면에 맞는 모양으로 옮긴다(2026-11-14, 사용 안내의 기능을 하나씩 대조): 오른쪽 클릭 → ⋯ 와 길게 누르기의 시트, 열 제목 → 정렬 시트, ⌘클릭 → "선택" 상태, 줄 끌기 → ≡ 손잡이, 사이드바 고정 → 보관함 맨 위, 오른쪽 패널 → 플레이어의 보기와 곡 정보 시트.
  같은 데이터와 같은 동작(`Action`, `ListState`의 정렬·선택, `settings.pinned`, 곡 정보의 줄 `info_rows`, 파일 검사 카드)을 쓰므로 데스크톱과 결과가 같다.
  그때 넣지 않은 것: 출력 장치 선택·샘플레이트 맞춤·독점, 키보드 단축키, 열 고르기, Apple Music 보관함 가져오기.
- 남겨 둔 것 가운데 할 수 있는 것을 넣었다(2026-11-15): 목록 안에서 찾기, 재생 중인 곡을 곡 목록에서 보기, 대기열에서 여러 곡 고르기, 바깥 폴더를 복사 없이 연결(북마크로 권한을 되찾고, 옮겨진 폴더는 경로를 따라감), 폴더 변화 감지(감시기 대신 30초마다 — iOS의 감시기는 파일마다 핸들을 열어 둠), 곡의 샘플레이트를 오디오 세션에 요청, Apple Music 보관함 가져오기(경로의 끝으로 곡을 찾음), 가로 화면.
  넣지 않은 것: 출력 장치 선택과 독점(iPhone에 그런 것이 없음), 외장 키보드 단축키(winit이 iOS에서 글자 입력만 넘겨주고, 실제 키보드 없이 확인할 수 없음), 열 고르기, iPad용 화면(폰 화면을 늘리는 것으로는 부족하고 따로 설계해야 함).
- macOS와 iOS가 같이 쓰는 코드는 `platform::apple`로 옮겼다(Now Playing, CP949 변환, 언어, 메모리 크기, 메인 스레드 실행).
- 기기용 앱은 Xcode 프로젝트(`ios/OnEum.xcodeproj`)가 만든다. 빌드 단계에서 cargo로 만든 실행 파일을 번들에 넣고 Xcode가 서명한다.

## 남은 위험
- **실제 기기에서는 실행까지만 확인.** 화면과 조작, 재생, 잠금 화면·제어 센터의 재생 제어, 전화 끊김, 이어폰 분리, 블루투스·AirPlay, 실제 메모리 한도, 배터리, USB DAC는 기기에서 사람이 봐야 한다.
- winit의 창 클래스 이름(`WinitUIWindow`)과 안전 영역을 읽는 방식에 의존한다. 클래스가 없으면 경고를 남기고 화면이 늘어난 채로 그려진다.
  winit이 씬을 지원하고 eframe이 표면 크기를 맞추면 1·2번 대응은 걷어 낸다.
- 화면 전환, 뒤로 가기 스와이프, 끌어내려 닫기는 egui로 직접 만든 것이라 iOS 기본 동작과 속도·탄성이 같지 않다(목록 끝의 튕김 없음). 시뮬레이터(60Hz)에서만 봤고 실제 기기의 120Hz 화면에서는 보지 못했다.
- winit의 iOS 쪽에는 화면 주사율에 맞춰 그리게 하는 장치가 따로 없다. `CADisableMinimumFrameDurationOnPhone`을 켜 두었지만 Pro 화면에서 실제로 120Hz로 그려지는지는 기기에서 재지 않았다.
- 줄을 끌어 옮기는 손잡이(≡)는 목록의 스크롤과 같은 손짓을 나눠 쓴다. 손잡이에서 시작한 끌기만 옮기기가 되는데, 실제 손가락에서 잘못 잡히는 일이 없는지는 기기에서 봐야 한다.
- 스크롤 막대를 잡을 수 있는 오른쪽 끝 10pt는 누르기만 해도 목록이 그 위치로 간다. 긴 목록을 빨리 지나가는 수단이지만 실수로 눌릴 수 있다.
