## 포맷 지원표
확장자·컨테이너·코덱을 구분합니다. "재생"은 오프라인 디코딩 테스트와 실제 장치 재생을 모두 통과했다는 뜻입니다.

| 확장자 | 컨테이너 | 코덱 | 재생 | Gapless | 근거 |
|---|---|---|---|---|---|
| .flac | FLAC | FLAC (16/24bit, 44.1~96kHz 확인) | ✅🖥 | **보장** — 샘플 단위 일치 | 이어 붙인 출력이 원본 연속 신호와 차이 0 |
| .wav | RIFF WAVE | PCM (16bit 확인) | ✅🖥 | **보장** — 샘플 단위 일치 | 〃 |
| .aif .aiff | AIFF | PCM (16bit 확인) | ✅🖥 | **보장** — 샘플 단위 일치 | 〃 |
| .m4a .mp4 .m4b | MP4 | ALAC | ✅🖥 | **보장** — 샘플 단위 일치 | 〃 |
| .mp3 | MPEG 오디오 | MP3 (Layer III) | ✅🖥 | **보장** — LAME/Xing 지연·패딩 정보가 있을 때 | 두 파일 합계 88,200프레임 = 원본과 동일, 경계 근처 연속 신호 대비 최대 오차 0.011, 무음 삽입 없음 |
| .m4a .mp4 .m4b | MP4 | AAC-LC | ✅🖥 | **보장하지 않음** | 인코더 지연이 제거되지 않음: 두 파일 합계 92,160프레임(원본 88,200), 경계에 무음 구간 측정됨 |
| .ogg .oga | Ogg | Vorbis | ✅🖥 | **보장하지 않음** | 두 파일 합계 88,320프레임(원본 88,200), 경계에서 레벨 저하 측정됨 |
| .m4a | MP4 | HE-AAC 등 AAC-LC 외 | ⏳ 확인 안 함 | — | 테스트 파일 없음 |
| .m4p 등 | MP4 | DRM 보호 | ❌ | — | 스캔에서 제외하고 "지원하지 않는 파일"로 집계 |
| .ogg | Ogg | Opus | ❌ | — | 〃 |
| .mp3 / .wav / .aiff | — | MPEG Layer I·II, ADPCM, 압축 AIFF-C | ❌ | — | 〃 |

Gapless 조건과 한계:
- 보장 범위는 **자연스럽게 다음 곡으로 넘어갈 때**입니다. 사용자가 곡을 바꾸거나 seek하면 짧은 페이드(6ms)가 들어갑니다.
- 무음을 잘라내거나 크로스페이드로 흉내 내지 않습니다. 같은 디코드 스레드가 같은 버퍼에 이어 씁니다.
- 곡의 샘플레이트가 출력 장치와 달라 리샘플링할 때도, **두 곡의 샘플레이트가 같으면** 리샘플러 하나를 이어 써서 연속입니다(44.1→48kHz에서 경계 불연속 없음 확인). 두 곡의 샘플레이트가 서로 다르면 리샘플러를 새로 시작하므로 샘플 단위 연속은 보장하지 않습니다(무음은 넣지 않음).
- 곡 기준 ReplayGain에서는 곡마다 이득이 달라 이어지는 앨범에서 음량 단차가 생길 수 있습니다. 그런 앨범은 앨범 기준을 쓰세요.
- 대기열 끝에서 "전체 반복 + 셔플"로 다시 섞을 때는 새 피드를 시작하므로 짧은 틈이 있습니다.
- Seek 정확도: 무손실 포맷은 요청한 프레임에서 정확히 시작(샘플 일치). MP3·Vorbis는 요청 위치에서 시작(연속 신호 대비 오차 0.011 / 0.004). AAC는 인코더 지연만큼 어긋날 수 있습니다.

파일 오류: 재생 중인 라이브러리에서 파일을 지움 → 플레이리스트에 있는 곡은 ⚠ 표시로 남고 나머지는 목록에서 빠짐 → 누락 곡 재생 시 "파일을 찾을 수 없어 건너뛰었습니다" 알림 후 다음 곡 재생. 파일을 폴더에 추가하면 5초 안에 목록에 나타남. 분리된(없는) 루트의 5만 곡을 재생하면 10곡 연속 실패 후 멈추고 안내.

장치 분리(실제 발생): 재생 중 FiiO K17이 시스템에서 사라지고 기본 장치가 Mac mini 스피커로 바뀜 → OnEum은 스피커로 넘어가지 않고 **일시정지 + "출력 장치 연결이 끊겨 일시정지했습니다" 알림**. "기본 장치로 재생"을 누르자 Mac mini 스피커(48kHz)에서 멈췄던 위치부터 재개.

그 밖에 번들에서 확인한 것:
- 한글 입력: 두벌식 입력기에 실제 키 이벤트로 `한글 음악` 조합, 조합 중 백스페이스, 입력 소스 전환 시 확정.
  (입력 소스를 프로그램으로 바꾼 직후 첫 몇 타는 조합되지 않음 — 입력기 활성화 지연이며 두 번째 입력부터 정상.)
- 네이티브 편집 메뉴를 통한 전체 선택·복사·붙여넣기가 검색 칸에 적용됨. 텍스트 입력 중 ⌘←는 커서를 옮기고 곡을 바꾸지 않음.
- 메뉴 단축키: ⌘→ 다음 곡, ⌘F 검색, ⌘↑ 볼륨, ⌘W 창 숨김(재생·앱 유지) → Dock 재열기 이벤트로 창 복원, ⌘Q 종료 시 상태 저장.
- Finder 열기: 실행 중 파일 열기 → 등록 후 재생. 파일로 앱을 시작 → 시작과 함께 재생. `.m3u8` 열기 → 플레이리스트 생성(2곡 일치, 1개 누락 안내).
- 실행 중 언어 전환(메뉴 재구성), 화면 모드 전환, 설정 파일 저장.
- 최소 창 크기(760×480)에서 검색·사이드바·목록·재생 제어·탐색 바·볼륨이 모두 보이고 표 열이 창에 맞게 줄어듦.
- 접근성 트리: 검색 칸(AXSearchField "검색"), 모든 아이콘 버튼(재생, 이전 곡, 다음 곡, 셔플, 반복, 볼륨, 설정, 재생 대기열, 곡 정보, 새 플레이리스트)에 이름이 노출됨.

## 알려진 문제
- 한 앨범의 파일이 여러 폴더에 흩어져 있고 일부에만 "앨범 아티스트" 태그가 있으면 앨범이 나뉘어 보일 수 있습니다(같은 폴더 안에서는 합쳐 보여 줍니다).
- AAC·Ogg Vorbis는 곡 사이에 짧은 틈이 생길 수 있습니다(위 지원표).
- 다채널(5.1/7.1) 파일은 스테레오로 다운믹스합니다.
- 창이 가려져 있으면 macOS가 화면 갱신을 멈춥니다(재생·미디어 키·Now Playing은 영향 없음).
- 의존성 고지는 목록(`THIRD_PARTY_NOTICES.md`)만 포함합니다. 각 라이선스 전문 묶음은 공개 배포 전에 추가해야 합니다(docs/RELEASE.md).
- 스캔할 때 내장 이미지를 파일마다 읽으므로, 큰 표지가 들어 있는 대규모 라이브러리를 느린 저장장치에서 처음 스캔하면 시간이 걸릴 수 있습니다.

## 앱 구동 검증
화면 녹화 권한 없이 실제 앱을 확인하기 위한 개발용 통로입니다. `ONEUM_SCRIPT`가 설정된 경우에만 동작합니다(`src/ui/automation.rs`).

```bash
scripts/dev/gen-test-library.sh /tmp/oneum-music
```
```bash
scripts/dev/run.sh /tmp/oneum-profile
```
```bash
scripts/dev/ui.sh /tmp/oneum-profile 'open /tmp/oneum-music' 'wait 2000' 'dclick 300 93' 'wait 1500' 'dump state.json' 'shot shot.png'
```

스모크 테스트(새 프로필 + 합성 라이브러리로 앱을 띄워 29개 항목을 자동 확인, 무음):
```bash
scripts/dev/smoke.sh
```
첫 실행 → 폴더 추가 → 한글·초성·다중 단어 검색 → 더블클릭 재생 → Space → 다음/이전/탐색 → 셔플·반복 → 앨범·아티스트 보기 → 즐겨찾기 → 대기열 패널 → 종료 후 재실행 복원까지 확인합니다. 2026-11-12 기준 3회 연속 통과.

- `click/dclick/rclick/drag/scroll/key/text`는 egui 입력 이벤트로 들어가므로 실제 마우스·키보드와 같은 경로를 탑니다.
- `oskey`는 OS 키 이벤트를 앱 이벤트 큐에 넣어 메뉴 단축키·응답 체인·입력기를 거칩니다.
- `dump`는 상태(JSON), `shot`은 앱이 그린 화면(PNG)을 프로필 폴더에 씁니다.
- 프로필은 `ONEUM_DATA_DIR`로 분리되어 실제 사용자 데이터에 닿지 않습니다. 기본으로 미디어 세션을 끄고(`ONEUM_MEDIA=1`로 켬) 다른 앱의 미디어 키를 가로채지 않습니다.
- 시스템 Now Playing 확인: `swift scripts/dev/nowplaying-probe.swift [pid 명령번호]` (비공개 MediaRemote API를 쓰는 진단 도구이며 앱에는 포함되지 않습니다).
