# OnEum 아키텍처

단일 crate(`oneum`)를 모듈로 나눈다. crate 분리는 필요가 생길 때 한다.

## 모듈과 책임
| 모듈 | 책임 |
|---|---|
| `app` | 초기화, 경로, 로그, 설정, 수명주기, 모듈 연결(플레이어↔라이브러리) |
| `i18n` | 한국어·영어 문자열 |
| `ui` | egui 화면, 입력, 테마, 다국어, 접근성 이름. 미터 덱(`meter`, `spectrum`), 앱 안 사용 안내(`guide`), 창 안 메뉴 막대(`menubar`, 시스템 메뉴가 없는 곳) |
| `playback` | 대기열 모델(순수 로직), 재생 상태, 명령 처리 스레드(`Player`) |
| `audio` | 디코딩(AAC의 지연·패딩 제거 `mp4_edit`), 메모리 재생 소스, 리샘플링, ReplayGain, 이퀄라이저·파라메트릭 보정(`peq`)·크로스피드·피크 보호, PCM 링 버퍼, 출력 콜백, 장치와 출력 품질 옵션, 음량 측정(`loudness`) |
| `library` | 스캔, 메타데이터, 메모리 인덱스와 검색(필드 지정 포함), 앨범 이미지, 파일 감시, M3U8, 가사(`lyrics`)·크레딧(`details`), 라디오 선곡, 태그 없는 곡의 음량 분석 작업(`loudness`) |
| `storage` | SQLite 스키마·마이그레이션, 설정 파일 |
| `net` | 같은 네트워크의 미디어 서버(DLNA/UPnP)와의 통신: HTTP/1.1 클라이언트(`http`), 서버 찾기(`ssdp`), 장치 설명과 폴더 읽기(`upnp`), 작은 XML 해석기(`xml`). 표준 라이브러리의 소켓만 쓴다(TLS 없음, `http://`만) |
| `platform` | 시스템별 구현을 같은 이름으로 내보내는 창구. 앱의 나머지는 어느 시스템인지 모른다. 모든 `unsafe`는 이 아래에 둔다 |
| `platform::macos` | 메뉴, Now Playing·미디어 명령, Finder 연동, 창 숨김/복원, 잠자기 알림, CoreAudio 장치 제어(샘플레이트·하드웨어 포맷·독점 접근) |
| `platform::windows` | 탐색기 연동, 시스템 언어, 그리고 Windows에 없는 것·구현하지 않은 것의 중립적인 대역(아래 "플랫폼") |
| `platform::apple` | macOS와 iOS가 같이 쓰는 것: Now Playing·미디어 명령(MediaPlayer), CP949 변환, 시스템 언어, 설치된 메모리, 메인 스레드 실행 |
| `platform::ios` | 씬 델리게이트(`scene`: winit의 창을 씬에 넣기, 파일 열기, 안전 영역, 키보드 높이, 화면 모드), 오디오 세션(`sound`), 문서 선택기와 가져오기(`files`), 백그라운드 진입·복귀(`lifecycle`) |
| `ui::phone` | 폰 화면: 아래 탭, 탭마다 화면 스택(밀려 들어오는 전환, 왼쪽 끝에서 뒤로 가는 스와이프), 미니 플레이어, 전체 화면 플레이어(표지·VU 미터와 스펙트럼·가사·대기열 가운데 하나를 보여 주고, 끌어내려 닫음), 아래에서 올라오는 시트, 보관함 맨 위의 고정. `ui::phone::edit`는 목록을 바꾸는 일(정렬, 여러 곡 고르기, 줄을 끌어 순서 바꾸기), `ui::phone::info`는 곡 정보 시트. 데스크톱과 같은 스냅샷·`Action`·목록 상태(`ListState`의 정렬·선택)를 쓰고, 미터·스펙트럼·설정 본문·이퀄라이저·곡 정보의 줄(`info_rows`)·파일 검사 카드는 데스크톱의 코드를 쓴다(`theme::touch`일 때 크기와 배치만 다름) |
| `model` | 모듈 사이에서 공유하는 값 타입(`Track`, `TrackId`, `ReplayGainTags`). `Track::leveling()`이 태그와 측정값을 합친, 음량 보정이 실제로 쓰는 값이다 |

## 실행 문맥
```
[UI 스레드] ──Command──▶ [Player 스레드] ──▶ [디코드 스레드] ──PCM 링──▶ [오디오 콜백]
     ▲                         │  ▲                                          │
     └── PlayerSnapshot ◀──────┘  └──── 재생 프레임 수 · underrun 카운터 ◀───┘
[미디어 키/메뉴/Finder] ──Command──▶ (같은 Player 채널)
[스캔 워커 N개] ──▶ [DB 기록] ──▶ 라이브러리 스냅숏 교체 ──▶ UI 다시 그리기 요청
```
- **UI 스레드**(메인): 그리기와 입력만. 디코딩·스캔·태그 읽기·이미지 처리를 하지 않는다. 메모리 스냅숏을 읽고, DB에는 보기가 바뀔 때의 짧은 조회(최근 재생)만 한다. 사용자의 편집(즐겨찾기, 플레이리스트, 곡 제거)은 편집 스레드 하나가 받은 순서대로 실행하고(`ui::background`) 결과를 이벤트로 돌려준다. 그래서 스캔이 DB를 쥐고 있거나 다른 프로그램이 파일을 잠가도 화면은 멈추지 않고, 실행 취소가 그 앞의 삭제를 앞지르지 않는다. 설정 파일은 또 다른 스레드가 최신 값만 기록한다(종료할 때 남은 것은 마지막에 직접). 플레이어에는 `Command`를 보내고
  `PlayerSnapshot`을 읽는다. 라이브러리는 불변 스냅숏(`Arc<LibrarySnapshot>`)을 읽는다.
- **Player 스레드**: 모든 재생 명령의 단일 진입점. GUI·메뉴·미디어 키·Finder가 같은 채널을 쓴다.
  대기열과 상태 기계를 소유하고, 20ms 주기로 콜백 카운터를 읽어 위치·곡 경계·오류를 처리한다.
- **디코드 스레드**(피드당 1개): 파일 읽기 → 디먹싱·디코딩 → 채널 매핑 → ReplayGain → 리샘플링 → 이퀄라이저 → 크로스피드 → 피크 보호 → 링 버퍼 쓰기.
- **오디오 콜백**(실시간): 링 버퍼에서 읽어 볼륨 램프를 곱해 장치 버퍼에 쓴다. 파일·DB·락 대기·할당·로그 없음.
  버퍼가 모자라면 무음을 쓰고 원자 카운터를 올린다.
- **스캔 워커**: 디렉터리 순회 1개 + 태그 읽기 워커(최대 4개) + DB 기록. 채널 용량으로 메모리를 제한한다.

## 오디오 경로
```
파일 → Symphonia(디먹싱·디코딩, gapless trim) → f32 인터리브 → 스테레오 매핑
     → ReplayGain(곡별 선형 이득, 변경 시 램프) → rubato 리샘플(필요할 때만)
     → 이퀄라이저(켜져 있고 0dB가 아닐 때만) → 크로스피드(켜져 있을 때만)
     → 피크 보호(0dBFS를 넘는 샘플이 있을 때만) → rtrb SPSC 링(약 1초)
     → 콜백: 볼륨 램프·일시정지 페이드 → 장치
```
- **피드(Feed)**: 링 버퍼 하나와 그것을 채우는 디코드 스레드 하나. 곡을 새로 시작하거나 seek할 때마다
  새 피드를 만든다. 콜백은 대기 없는 큐로 새 소비자(consumer)를 받아 이전 것을 짧게 페이드아웃한 뒤 교체하고,
  이전 소비자는 반환 큐로 돌려보내 다른 스레드에서 해제한다. 이전 피드의 디코드 결과는 아무도 읽지 않는
  링에 쓰이므로 새 곡에 섞일 수 없다(세대 분리).
- **Gapless**: 곡이 자연스럽게 끝나면 같은 피드의 디코드 스레드가 다음 곡을 이어서 같은 링에 쓴다.
  스트림을 끊지 않고 무음 삽입·제거·크로스페이드도 하지 않는다. 경계는 "피드 시작부터 N번째 프레임"으로
  기록하고 Player가 재생 프레임 수와 비교해 현재 곡을 바꾼다.
- **위치**: `(콜백이 소비한 프레임 − 곡 시작 프레임 − 출력 지연) / 샘플레이트 + seek 기준`.
- **재생 횟수**: 한 번의 "듣기"마다 실제로 들린 시간을 Player가 피드와 따로 누적한다. 곡 길이의 절반(최대 4분)을
  들으면 1회로 센다. seek·대기열 편집·장치 변경으로 피드를 새로 만들어도 같은 듣기이므로 다시 세지 않고,
  끝부분으로 건너뛰어 끝난 곡은 세지 않는다. 같은 곡을 다시 고르거나 반복 1곡으로 돌아오면 새 듣기다.
- **멈춤 감시**: 재생을 원하는데 일정 시간(기본 15초) 소리가 나오지 않으면, 디코드 쪽에 데이터가 없을 때는
  그 곡을 "읽을 수 없음"으로 건너뛰고(죽은 드라이브에서 멈춘 읽기), 데이터가 대기 중인데 장치가 가져가지 않을 때는
  출력 장치 문제로 알린다. 디코드 스레드의 panic은 그 곡의 실패로 바뀌어 피드가 정상 종료된다.
- **응답 없는 장치**: 재생 스레드는 루프를 돌 때마다(초당 5회 이상) 시각을 적어 둔다. 장치 드라이버가 멈춰 호출이 돌아오지 않으면 이 신호가 끊기고,
  12초 넘게 끊기면 UI가 "출력 장치가 응답하지 않습니다"를 알린다(멈춘 호출을 되살릴 수는 없다). 종료할 때 재생 스레드는 8초까지만 기다린다.
- **일시정지 후 해제**: 30초 넘게 일시정지 상태면 피드를 놓아 파일을 닫는다(외장 드라이브를 꺼낼 수 있게).
  다시 재생하면 같은 위치에서 새 피드를 만든다.
- **출력 형식**: 기본은 장치의 현재 설정(샘플레이트·채널·형식)을 따르고 장치 설정을 바꾸지 않는다.
  곡의 샘플레이트가 다르면 리샘플링한다. 사용자가 켠 경우에만 아래 "출력 품질 옵션"대로 장치를 바꾼다.
- **볼륨**: 앱 볼륨은 콜백에서 램프로 적용(시스템 볼륨과 별개). ReplayGain은 디코드 스레드에서 적용.
- **스펙트럼 표시**: 콜백이 좌우를 합친 샘플을 원자 변수 배열(`Scope`, 최근 8,192개)에 적고, UI가 미터 덱이 보일 때만 읽어
  2,048점 FFT(Hann 창)로 40Hz~16kHz를 로그 간격 36대역으로 나눈다(`ui::spectrum`). 88.2kHz 이상에서는 이웃 샘플을 평균해 44.1~48kHz로 낮춘 뒤
  분석한다(저음 해상도 유지). 막대는 즉시 오르고 일정한 속도로 내려오며, 재생이 멈춰 모두 꺼지면 화면을 다시 그리지 않는다.
- **레벨 측정(VU 미터)**: 콜백이 버퍼마다 좌우 채널의 절댓값 평균과 최댓값을 원자 변수에 적는다(`LevelMeter`, 할당·락 없음).
  측정 지점은 페이드 뒤·앱 볼륨 앞이다. UI는 미터 덱이 보일 때만 이 값을 읽어 바늘을 2차 감쇠계(ω=13.9rad/s, ζ=0.8)로
  움직인다(`ui::meter`). 재생 중이거나 바늘이 아직 움직일 때만 다음 프레임을 요청하므로, 멈춘 화면은 다시 그리지 않는다.
  스트림을 닫으면 콜백이 더 돌지 않으므로 측정값을 0으로 되돌린다.
- **장치**: 스트림은 항상 특정 장치 ID로 연다(기본 장치 자동 추종 스트림은 쓰지 않는다 — 헤드폰이 뽑히면
  스피커로 넘어가기 때문). 장치가 사라지면 일시정지하고 사용자에게 알린다. "시스템 기본" 모드에서 사용자가
  기본 장치를 바꾸면(이전 장치가 살아 있는 채로) 새 기본 장치로 스트림을 옮긴다.
  장치 오류 콜백은 실시간 스레드에서 올 수 있으므로 원자 플래그만 세운다(할당·락·채널 없음).
  장치 목록 조회 실패는 "분리"로 보지 않고, 목록에서 두 번 연속 빠져야 분리로 판단한다.
  스트림 무효화 알림이 왔을 때 원래 장치가 사라졌으면 기본 장치로 옮기지 않고 일시정지한다.

### 출력 품질 옵션
설정 → 재생의 스위치 세 개. 모두 기본은 꺼짐이고, 꺼져 있으면 위의 동작과 완전히 같다.
- **곡의 샘플레이트로 출력**: 곡을 시작하기 전에 장치의 클럭을 그 곡의 샘플레이트로 맞춘다. 곡의 샘플레이트는
  라이브러리가 읽어 둔 값을 쓴다(파일을 열기 전에 장치를 준비해야 하므로). 값을 모르는 곡은 건드리지 않고 평소처럼 변환한다.
  - 장치가 그 샘플레이트를 지원하지 않으면: 가장 작은 정수배(22.05→44.1) →
    바로 위의 샘플레이트 → 가장 높은 샘플레이트 순으로 고른다(`audio::output::choose_rate`).
    곡보다 낮은 샘플레이트는 그 이상이 하나도 없을 때만 쓴다(파일에 담긴 대역을 잘라 내지 않기 위해). 두 샘플레이트가 단순한 비율인지는
    따지지 않는다: 변환 품질이 비율과 무관함을 측정으로 확인했다(아래 "리샘플링 품질").
  - 샘플레이트를 먼저 바꾸고, 그 샘플레이트에서 장치가 더 넓은 하드웨어 포맷(비트 깊이)을 제공하면 그것으로 바꾼다.
    파이프라인이 32비트 부동소수점이므로 32비트보다 넓은 포맷은 고르지 않는다. 포맷 변경 실패는 오류가 아니다.
  - **Gapless와의 관계**: 한 피드는 한 샘플레이트로만 이어진다. 다음 곡이 다른 장치 샘플레이트를 요구하면 플레이어가
    디코드 스레드에 "다음 곡 없음"을 알려 피드를 곡 경계에서 끝내고, 장치를 바꾼 뒤 새 피드를 시작한다.
    샘플레이트가 같은 곡끼리는 종전처럼 같은 링에 이어 쓴다.
  - 피드가 끝난 직후 스트림을 닫을 때는 장치가 이미 받은 소리(출력 지연만큼)가 다 나올 때까지 기다린다(최대 0.5초).
  - 우리가 바꾼 샘플레이트의 변경 알림이 새 스트림을 연 뒤에 늦게 도착할 수 있다. 장치가 스트림과 같은 샘플레이트로
    돌고 있으면 그 알림은 무시한다(다시 열면 또 알림이 와서 반복되기 때문).
- **독점 출력**: 스트림을 여는 동안 CoreAudio의 독점 접근(hog mode)을 잡는다. 다른 앱은 그 장치로 소리를 낼 수 없고
  포맷도 바꿀 수 없다. 거부되면(다른 앱이 이미 독점) 공유 상태로 재생하고 곡 정보에 "독점"을 표시하지 않는다.
  독점 중에는 macOS가 시스템 기본 장치를 다른 곳으로 돌려 두므로, "시스템 기본 장치" 설정이어도 잡은 장치에 머문다.
- **되돌리기**: 장치를 건드린 동안의 상태(`DeviceHold`)는 스트림과 별개로 엔진이 갖고 있다가, 출력을 실제로 닫을 때
  원래 샘플레이트·포맷으로 되돌리고 독점을 푼다 — 대기열 끝, 정지, 30초 넘는 일시정지, 장치 변경, 잠자기, 종료.
  곡 사이에서 샘플레이트만 바꿀 때는 되돌리지 않는다(두 번 바꾸지 않도록). 비정상 종료 시에는 샘플레이트가 남는다(독점은 시스템이 푼다).
- **메모리 재생**: 파일을 백그라운드에서 메모리로 읽어 들이면서 동시에 디코딩한다(`audio::source`). 읽힌 부분은 메모리에서, 파일 전체가 메모리에 올라오면 디스크의 파일 핸들은 놓는다(핸들은 메모리 데이터와 함께 공유 상태가 가지고, 다 읽은 로더가 놓는다): 다음 곡을 위해 데이터를 들고 있는 동안에도 그 드라이브를 꺼낼 수 있다.
  아직 안 읽힌 부분은 파일에서 직접 읽으므로 시작과 탐색이 늦어지지 않는다. 다 읽으면 파일을 닫는다.
  현재 곡을 다 읽은 뒤에는 예고된 다음 곡을 미리 읽어 둔다(한 번에 한 파일). 1GiB를 넘는 파일은 평소처럼 디스크에서 읽는다.
  동시에 메모리에 있는 파일은 최대 두 개(현재 곡과 다음 곡)이고, 둘을 합쳐 설치 메모리의 1/8(최대 1.5GiB, 알 수 없으면 512MiB) 안이다(`source::Budget`). 남은 예산에 들지 않는 파일은 디스크에서 읽는다.
- **곡 정보의 "출력"·"처리"**: 장치·샘플레이트·하드웨어 포맷·독점 여부와, 앱이 샘플에 하는 일(리샘플링, 채널 변환,
  음량 보정, 피크 보호, 앱 볼륨)을 그대로 보여 준다. "없음"은 앱 안에서 디코더의 샘플이 그대로 출력 콜백에 전달된다는 뜻이고
  (자동 테스트로 확인), 그 뒤 CoreAudio·드라이버·DAC 구간은 앱이 확인할 수 없다. 그래서 "bit-perfect"라고 쓰지 않는다.

### 곡의 시작과 페이드
콜백은 재생이 파형 한가운데에서 시작하거나 멈출 때(일시정지·재개, 탐색, 다른 곡으로 바꿀 때 나가는 쪽) 6ms 페이드로 클릭을 막는다.
**곡을 처음부터 재생할 때는 페이드인하지 않는다**(`FeedConsumer::from_start`): 곡이 어떻게 시작하는지는 곡의 일부이고, 첫 박에 바로 시작하는 곡의
어택이 페이드로 깎이기 때문이다. 그래서 "처리 없음"인 재생은 첫 샘플부터 마지막 샘플까지 파일과 비트 단위로 같다(통합 테스트).
곡 사이의 gapless 전환에는 원래 페이드가 없다.

### 리샘플링 품질
`audio::resample`은 rubato의 FFT 동기 리샘플러를 쓰되, FFT 블록 길이(=안티에일리어싱 필터 길이)를 **두 샘플레이트 중 낮은 쪽 기준 512프레임**으로
잡는다. rubato의 기본값은 입력 샘플레이트만 보고 블록을 정해서, 96·192kHz → 44.1kHz에서는 블록이 147프레임이 되어 20kHz가 5.6dB 깎였다(측정).
지금 값에서의 측정 결과(단위 테스트로 고정, −1dBFS 사인파, 44.1↔48, 44.1↔96, 44.1→88.2, 96→48, 192→44.1/48):

| 항목 | 결과 |
|---|---|
| 통과 대역 | 100Hz~20kHz에서 ±0.001dB 이내 |
| 왜곡+잡음 | SINAD 125dB 이상(실측 약 135dB — 32비트 float 샘플의 한계) |
| 다운샘플링 에일리어싱 | 새 나이퀴스트의 1.01~1.6배 신호가 −120dB 아래(실측 약 −140dB) |
| 업샘플링 이미지 | 20kHz의 이미지(24.1kHz)가 −120dB 아래 |

필터가 길어진 만큼 프리링잉 구간도 길어지지만 그 주파수는 21kHz 위다. 처리 속도는 피크 보호를 포함해 가장 느린 44.1→192kHz에서도 실시간의 약 360배(릴리스 빌드, 이 Mac)다.

### 피크 보호
파일의 샘플이 풀스케일을 넘지 않아도, 장치로 나갈 때는 넘을 수 있다. 음량을 꽉 채운 음원은 **샘플과 샘플 사이**의 파형이 풀스케일을 넘고
(inter-sample over, 리샘플링하면 드러난다), 손실 코덱은 디코드하면 원본보다 커지기도 하며, 양수 ReplayGain도 더해진다. 장치는 그런 샘플을 잘라 내고(클리핑)
그것은 왜곡이다. `audio::limiter`는 링 버퍼 바로 앞에서 그런 피크 주변 몇 ms 동안만 이득을 필요한 만큼 낮춘다.
- 1.5ms 앞을 내다보고(그만큼 지연) 이득을 직선으로 내린 뒤, 시정수 100ms로 되돌린다. 좌우 채널에 같은 이득을 쓴다.
- **풀스케일을 넘는 샘플이 없으면 아무것도 하지 않는다**: 출력은 입력과 비트 단위로 같다(단위·통합 테스트). 정수 PCM 파일을 변환 없이 재생할 때는
  넘는 샘플이 있을 수 없으므로 "처리 없음" 경로는 그대로다.
- 측정: +3dB 넘는 1kHz 사인파에서 클리핑은 왜곡 −25dB보다 나쁘고, 리미터는 −60dB 아래. 44.1kHz 파일의 fs/4 풀스케일 신호(샘플은 풀스케일, 파형은 +3dB)를
  48kHz로 변환하면 피크가 1.41이 되는데, 리미터를 거치면 1.0 이하이고 왜곡은 클리핑보다 25dB 이상 낮다(통합 테스트).
- 샘플 피크 기준이다(트루 피크 리미터가 아님). 리샘플링 뒤에 놓여 있어 변환으로 드러난 피크는 잡지만, 리샘플링하지 않는 경로에서 DAC 내부의
  재구성 필터가 만드는 피크는 앱이 볼 수 없다.
- 동작한 곡은 곡 정보와 미터 덱의 "처리"에 `피크 보호`로 표시된다(플레이어 스냅숏의 `peak_limited_frames`, 곡 단위).

### 이퀄라이저와 크로스피드
둘 다 디코드 스레드에서, 출력 샘플레이트로, 피크 보호 **앞**에서 돈다(`audio::eq`, `audio::crossfeed`). 올린 대역이 풀스케일을 넘기면 잘리지 않고 피크 보호가 받는다.
- **이퀄라이저**: 한 옥타브 간격 10대역(32Hz~16kHz) 피킹 필터(RBJ cookbook, Q=√2)와 프리앰프, 각 ±12dB. 계수와 상태는 64비트 부동소수점(192kHz에서 32Hz 필터도 정확하다).
  - 꺼져 있거나 모든 값이 0dB이면 경로에서 빠진다: 출력은 입력과 비트 단위로 같다(단위·통합 테스트).
  - 값이 바뀌면 32프레임마다 조금씩(초당 240dB) 옮겨 간다. 0dB로 돌아오면 0.5초 뒤(필터에 남은 울림이 사라진 뒤) 경로에서 빠진다.
  - 측정(단위 테스트): 각 대역 중심에서 설정값 ±0.05dB(44.1/96/192kHz), 화면의 곡선(`eq::response_db`)과 실제 소리의 차 0.05dB 이내, 값 변경·끄기에서 샘플 간 계단 없음.
  - 설정은 원자 변수(`EqShared`)로 디코드 스레드에 전달된다. 디코드가 재생보다 최대 1초 앞서 있으므로 바꾼 소리는 그만큼 뒤에 들린다(피드를 다시 만들지 않는다: 끊김이 없다).
  - 기본 프리셋 12개(`eq::BUILTIN_PRESETS`)의 프리앰프는 가장 많이 올린 대역만큼 내려 둔 값이다(풀스케일 신호가 넘지 않게). 사용자 프리셋은 `settings.json`의 `eq_presets`(이름·프리앰프·대역값, 40개까지).
    "선택된 프리셋"은 저장하지 않는다: 지금 값과 같은 프리셋이 선택된 것이다.
- **크로스피드**: bs2b(Bauer stereophonic-to-binaural)의 필터 쌍. 반대 채널로 가는 길에 1차 저역 통과, 제 채널에 그에 맞춘 하이 셸프. 세기 셋: 약하게(650Hz, 9.5dB), 보통(700Hz, 6dB), 강하게(700Hz, 4.5dB).
  - 측정(단위 테스트): 한쪽에만 있는 60Hz가 반대쪽에 설정한 레벨 차(±0.2dB)로 나타남, 8kHz는 20dB 이상 분리 유지, 가운데 소리는 저역 0dB·고역 −2dB 이내, 풀스케일 입력이 풀스케일을 넘지 않음.
  - 꺼져 있으면 비트 단위 통과. 켜기·끄기·세기 변경은 40ms 크로스페이드.
- 둘 다 "처리"로 센다: 정수 포맷 장치에는 디더가 들어가고, 신호 경로에 단계로 표시된다.

### 신호 경로 표시
곡 정보 패널의 "신호 경로"는 소스와 출력 사이의 단계를 **오디오가 지나는 순서대로** 보여 준다(`ui::panels::path_stages`): 채널 변환 → 음량 보정 → 리샘플링 → 이퀄라이저 → 크로스피드 → 피크 보호 → 앱 볼륨 → 디더.
단계는 이유로 나눈다: 장치에 맞춘 **변환**(리샘플링·채널·디더), 사용자가 켠 **조정**(음량 보정·이퀄라이저·크로스피드·앱 볼륨), **보호**(피크 보호). 요약은 "원본 그대로 / 사용자 조정 / 변환 / 변환 · 사용자 조정".
Roon의 신호 경로가 품질 등급(무손실·고음질 등)을 매기는 것과 달리, OnEum은 앱이 하는 일만 말한다: 앱 밖 구간을 확인할 수 없으므로 "무손실 출력"이라고 쓰지 않는다.

### 디더
정수 포맷으로 받는 장치(16·24비트)로 나가는 소리는 장치의 한 단계 크기로 반올림된다. 샘플이 파일 그대로일 때는 반올림할 것이 없으므로
아무것도 더하지 않는다. **파일 그대로가 아닐 때만** 콜백에서 TPDF 디더(±1 단계의 삼각 분포 잡음)를 더해, 반올림 오차가 신호에 따라 달라지는
왜곡이 아니라 일정한 잡음이 되게 한다.
- "파일 그대로가 아님"의 조건: 손실 코덱에서 디코드됨, 리샘플링함, 채널 변환함, ReplayGain 이득이 1이 아님, 원본 비트 깊이가 장치보다 넓음(또는 모름), 앱 볼륨이 100% 미만.
- 32비트 정수와 부동소수점 장치에는 넣지 않는다(파이프라인의 32비트 float가 담는 24비트보다 세밀하다).
- 장치의 포맷은 CoreAudio에서 읽는다. 포맷을 알 수 없는 곳(Windows)에서는 넣지 않는다. 적용 중이면 곡 정보의 "처리"에 `디더 (16 bit)`처럼 표시한다.

### 다른 플레이어와 견준 설계 판단
재생 품질로 알려진 플레이어들이 공통으로 하는 일과, OnEum이 그것을 어떻게 했는지다. (각 제품의 내부는 공개 문서와 사용자 보고에 근거하며, 직접 측정한 것이 아니다.)

| 하는 일 | 다른 플레이어 | OnEum |
|---|---|---|

| 장치 샘플레이트 | 곡에 맞춰 전환(Audirvana, Roon, foobar2000의 독점 출력) | "곡의 샘플레이트로 출력"(macOS). 지원하지 않는 샘플레이트는 정수배 → 바로 위 → 가장 높은 샘플레이트 |

| 메모리 재생 | 곡 전체를 미리 디코드해 메모리에(Audirvana) | 파일을 메모리에 올리며 동시에 디코드, 다음 곡 미리 읽기 |

| 이어 재생 | Roon 라디오(온라인 추천) | 라디오: 라이브러리 안에서 장르·아티스트·연도로 고름(오프라인) |

### Roon에서 가져오지 않은 것
roon.app의 소개(음질, 음악 경험, 호환성)를 놓고 OnEum의 원칙(로컬 파일, 계정·서버·네트워크 없음)에 맞는 것만 가져왔다. 가져오지 않은 것과 이유:
- 온라인 메타데이터(아티스트 약력, 리뷰, 사진, 크레딧, 공연 일정, 가사 검색), 스트리밍 서비스 연동, 온라인 추천: 네트워크와 외부 서비스가 필요하다.
  파일의 태그에 이미 들어 있는 크레딧·작품 정보·싱크 가사는 보여 준다(아래 "가사와 크레딧"). 이름의 로마자 표기, 같은 곡의 스트리밍 버전 찾기도 같은 이유로 넣지 않았다.
- 멀티룸·AirPlay·Chromecast·Roon Ready 출력, 원격 조작(ARC): 네트워크 스트리밍 계층이 필요하다.
- MQA 재생, DSD를 그대로 내보내기(DoP), 멀티채널 출력: MQA는 비공개 포맷이고, 출력 경로가 스테레오이며 DoP는 모든 처리를 끈 비트 단위 경로가 있어야 한다. DSD는 PCM으로 바꿔 재생한다(아래 "DSD").
- 파라메트릭 EQ는 나중에 "보정값 파일 불러오기"의 형태로 넣었다(아래 "파라메트릭 보정"): 필터를 직접 설계하는 화면이 아니라, 남이 측정해 만든 값을 그대로 거는 용도다.
- 룸 보정·컨볼루션, 업샘플링 필터 선택: 측정 마이크와 필터 설계 도구가 있어야 쓸모가 있는 기능이라 넣지 않았다.

하지 않기로 한 것: 업샘플링 필터 고르기(같은 음원을 다르게 들리게 하는 선택지를 늘리지 않는다), 이퀄라이저·DSP 플러그인, 스트리밍.
디코더가 없어 재생하지 못하는 형식(Opus, WavPack, APE, DST 압축 DSD)은 스캔에서 "지원하지 않는 파일"로 센다.

### DSD
`audio::dsd`. DSF(소니, 리틀 엔디언, 채널마다 4,096바이트 블록, 끝에 ID3v2)와 DSDIFF(.dff, 빅 엔디언 IFF, 채널이 바이트 단위로 번갈아, `ID3 ` 청크)를 직접 읽는다. Symphonia에는 DSD가 없다.
- PCM으로 바꿔 재생한다: 44.1kHz 계열은 88.2kHz, 48kHz 계열은 96kHz. 그러면 나머지 경로(gapless, 음량 보정, 이퀄라이저, 미터, 샘플레이트 맞춤, 메모리 재생)가 그대로 쓰인다. 곡 정보에는 파일의 DSD 샘플레이트, 재생 결정(`Track::playback_rate`)에는 PCM 샘플레이트를 쓴다.
- 필터는 두 단계의 선형 위상 FIR이다. 1단계는 비트에서 PCM의 4배(352.8kHz)로: Kaiser 창 96탭(DSD64 기준, 샘플레이트에 비례해 길어짐)을 바이트 단위 표(256값 × 바이트 위치)로 계산하고, 0~40kHz로 접힐 대역을 135dB 넘게 막는다. 2단계는 125탭으로 PCM 샘플레이트로: 20kHz까지 ±0.0001dB, 30kHz에서 −6dB, 40kHz부터 −100dB 아래. DSD의 잡음 성형이 고음역 위로 밀어 둔 잡음을 걸러 낸다. 계산은 64비트.
- 레벨: 비트 1을 +1, 0을 −1로 두므로 이득을 더하지 않는다. SACD 기준 레벨(변조 50%)이 −6dBFS로 나온다. +6dB를 더하는 플레이어도 있지만, 그러면 기준보다 큰 구간마다 피크 보호가 동작하므로 더하지 않았다(음량 보정이 맞춘다).
- 필터가 앞을 내다보는 만큼(16 PCM 프레임, 약 0.18ms) 곡의 끝은 다음에 무엇이 오는지에 달려 있다. 디코드 스레드는 DSD 곡이 끝나면 다음 곡을 먼저 열어(`TrackDecoder::finish`) 같은 종류의 DSD이면 그 곡의 첫 비트로 앞 곡의 마지막 프레임을 계산하고, 다음 곡은 앞 곡의 필터 상태에서 시작한다. 두 파일이 한 스트림처럼 변환되어(테스트로 차이 1e-6 미만 확인) 경계에 흔적이 없다. 다음이 PCM이거나 없으면 DSD 무음(0x69)으로 마무리한다.
- 탐색은 목표보다 40프레임 앞에서 필터를 무음으로 시작해 목표부터 내보낸다. 이어서 재생한 것과 같은 샘플이 나온다.
- 5.1(채널 타입 7, `MLFT MRGT C LFE LS RS`)과 그 밖의 다채널 배치는 5.1 순서의 6채널로 내보내 기존 다운믹스가 처리한다. DST 압축(`CMPR` = `DST `)은 지원하지 않는다.
- 독립 구현과의 대조: ffmpeg의 DSD 디코더로 같은 DSF·DFF를 디코드하면 레벨이 ±0.000dB로 같고, ffmpeg 쪽이 필터 지연을 남겨 14.17µs 늦다(주파수와 무관한 고정 지연). 우리 출력은 인코드한 신호와 1µs 안에서 맞는다.

### 해석기의 비용 상한
태그 라이브러리에 파일을 넘길 때는 읽는 양(256MB)과 호출 수(10만)에 상한을 둔 읽기 객체를 그 밑에 깐다(`tags::Budget`). 실제 음악 파일은 몇 MB와 수백 번이면 되고, 망가진 파일이 해석기를 아주 작은 걸음으로 끝없이 걷게 하는 경우(0으로 이어지는 FLAC 메타데이터)를 끊는다.
태그를 읽기 전, 음량 분석으로 디코드하기 전에 일반 파일인지 확인한다(파이프는 열면 끝없이 기다린다). 재생 디코더는 패킷 하나가 디코드될 때까지 128MB를 넘게 읽으면 곡이 거기서 끝난 것으로 본다(열 때 넘으면 망가진 파일). 탐색 중에 읽는 것은 세지 않는다: 목차가 없는 MP3의 정확한 탐색은 파일을 훑어야 한다. 재생 디코더에는 앞의 ID3v2 태그를 건너뛴 스트림을 준다(태그는 라이브러리에서 가져오며, 디코더는 태그의 프레임을 모두 메모리에 올린다).

### Matroska·WebM, ADPCM
Symphonia의 `mkv`·`adpcm` 기능을 켰다(MPL-2.0). 태그 라이브러리(lofty)가 Matroska를 모르므로 스캔은 디코더가 열어 본 정보(코덱, 샘플레이트, 세그먼트 길이)와 Symphonia가 읽은 태그를 쓴다. Matroska 태그는 대상 수준이 붙어 오므로("ALBUM@ARTIST") 앨범 수준의 제목은 앨범, 아티스트는 앨범 아티스트로 읽는다. ffmpeg처럼 곡 제목을 태그가 아닌 세그먼트 제목에 쓰는 파일은 파일 이름으로 보인다.
ADPCM WAV(Microsoft, IMA)는 디코더가 실제로 열 수 있을 때만 받는다(`can_play`).

### AAC의 지연과 패딩
AAC 인코더는 음악 앞에 준비 구간(ffmpeg 1,024프레임, Apple 2,112프레임)을 두고 끝을 패킷 단위로 채운다. 어디가 음악인지는 파일이 두 가지 방식 중 하나로 말한다:
편집 목록(`moov/trak/edts/elst`의 시작 위치와 길이)과 Apple의 `iTunSMPB` 메모(`moov/udta/meta/ilst/----`, 지연·패딩·음악 프레임 수). Symphonia의 MP4 리더는 편집 목록을 읽기만 하고 쓰지 않으며 메모는 보지 않으므로,
`audio::mp4_edit`가 파일에서 직접 읽어 `TrackDecoder`가 디코드한 프레임 가운데 그 구간만 내보낸다(곡 길이와 탐색 위치도 음악 기준으로 센다).
- `iTunSMPB`가 있으면 그것이 먼저다(프레임 수를 정확히 적는다). 편집 목록은 영화 시간 단위가 미디어보다 거칠 때(밀리초 등) 마지막 프레임을 가리킬 수 없으므로, 미디어 길이와 반올림 범위 안에서 맞으면 미디어 길이를 쓴다.
- 신뢰하지 않는 입력으로 다룬다: 상자의 크기는 바깥 상자 안에 들어가는지 확인하고, 살펴보는 상자 수와 읽는 내용의 크기에 한도를 두며, 지연이 1초를 넘으면 정보 전체를 버린다. 정보가 없으면 전과 같이 디코드되는 그대로 재생한다.
- Ogg Vorbis는 Symphonia가 파일의 위치 정보(granule position)로 직접 자르므로 손대지 않는다.

### 파라메트릭 보정 (헤드폰 보정)
`audio::peq`. 보정값 파일(Equalizer APO 형식: `Preamp:` 한 줄과 `Filter N: ON PK|LSC|HSC Fc … Hz Gain … dB Q …`)을 프로필로 읽어, 이퀄라이저와 크로스피드 사이에서 건다.
- 필터는 Audio EQ Cookbook의 바이쿼드(피킹, 로우 셸프, 하이 셸프 — 셸프는 중심 주파수와 Q)이고 64비트 TDF2로 계산한다. AutoEq가 쓰는 정의와 같다.
- 구현하지 않은 필터(LP·HP·LS·HS·노치·올패스, 기울기로 적은 셸프)가 하나라도 있으면 파일 전체를 거절한다. 일부만 건 보정은 다른 보정이기 때문이다. `OFF` 필터와 주석은 건너뛴다.
- 프로필이 없거나 아무것도 바꾸지 않으면 단계가 경로에서 빠진다(비트 단위 통과). 프로필을 바꾸면 이전 체인과 새 체인을 0.04초 동안 함께 돌려 크로스페이드한다. 샘플레이트의 45%를 넘는 필터는 걸지 않는다.
- 필터를 합친 올림(20Hz~20kHz 격자와 각 필터의 중심 주파수에서, 44.1·48·96·192kHz)이 12dB를 넘지 않게 프리앰프를 낮춘다. 필터 하나하나의 한도(±30dB)만으로는 32개가 한 주파수에 겹친 파일을 막지 못한다.
- 프로필은 `settings.json`에 값으로 저장한다(30개까지, 필터 32개까지, 값은 불러올 때 범위 안으로). 디코드 스레드와는 `Arc<Mutex<Option<Arc<프로필>>>>`과 버전 번호로 나눈다(디코드 스레드는 실시간 스레드가 아니다).
- 기본 프로필 35종은 `assets/corrections/headphones.txt`에 있고 빌드할 때 프로그램에 들어간다(`peq::builtin_profiles`, 처음 쓸 때 한 번 해석). 34종의 값은 AutoEq(`results/oratory1990`, MIT)의 `ParametricEQ.txt`를 고치지 않고 옮긴 것이고(Sennheiser Momentum 5 Wireless 하나는 AutoEq에 결과가 없어, Super* Review가 공개한 측정을 AutoEq 4.1.2로 같은 목표·같은 설정으로 계산한 `ParametricEQ.txt`를 옮겼다 — 절차는 그 파일 머리말과 docs/TESTING.md),
  프로필마다 `# check <숫자 개수> <합>` 줄이 있어 테스트가 파일의 숫자를 다시 세고 더해 대조한다(옮기다 틀린 값을 잡기 위한 것 — 합은 원본 페이지에서 계산했다). 설정에는 이름만 저장하고(`correction`),
  이름은 불러온 프로필에서 먼저 찾고 없으면 기본 프로필에서 찾는다. 기본 프로필은 `settings.json`에 복사하지 않는다. 라이선스 전문은 `assets/corrections/LICENSE-AutoEq.txt`이고 고지 문서 생성 스크립트 둘이 이 파일을 넣는다.
- 10밴드 이퀄라이저와 따로 둔 이유: 보정은 헤드폰에 맞춘 고정값이고 이퀄라이저는 취향이라, 하나를 바꿀 때 다른 하나가 지워지면 안 된다.

### 채널 매핑
출력 경로는 스테레오다. 디코드한 직후에 스테레오로 맞춘다(`audio::dsp::to_stereo`): 모노는 양쪽에 같은 신호를, 5.1·7.1(표준 순서 FL FR FC LFE, 서라운드)은
`L = FL + 0.707·FC + 0.707·(왼쪽 서라운드들)`, R도 같은 식으로 만들고 계수의 합(5.1은 2.414, 7.1은 3.121)으로 나눠 입력 피크를 넘지 않게 한다. LFE는 넣지 않는다.
그 밖의 채널 수는 짝수 번째 채널을 왼쪽, 홀수 번째를 오른쪽으로 평균한다. 디코더가 포맷마다 다른 저장 순서를 표준 순서로 돌려 주는 것(FLAC, WAV, AIFF, ALAC)과 이 식을 테스트로 고정했다.
신호 경로에는 "채널 변환"으로 나온다. 음량 측정도 이 매핑을 거친 신호로 한다.

### ReplayGain 정책
- 모드: 끔 / 곡 / 앨범. 앨범 모드에서 앨범 값이 없으면 곡 값을 쓴다(반대도 같음). 둘 다 없으면 보정하지 않는다.
- 값의 출처: 파일의 태그가 먼저다. 태그에 곡 이득이 없으면 앱이 측정한 값을, 앨범 이득이 없으면 측정한 앨범 값을 쓴다(아래 "음량 분석"). 이득과 피크는 언제나 같은 출처에서 함께 온다.
- 이득 = 값(dB) + 프리앰프(dB, 기본 0). 값이 없는 곡에는 프리앰프도 적용하지 않는다.
- 클리핑 방지(기본 켬): peak 태그가 있으면 `이득 × peak ≤ 1.0`이 되도록 이득을 낮춘다.
  peak 태그가 없으면 이득을 0dB 이하로 제한한다(증폭하지 않음).
- 적용 순서: 디코드 → ReplayGain(프리앰프 포함, 클리핑 방지 반영) → 리샘플 → 이퀄라이저 → 헤드폰 보정 → 크로스피드 → 피크 보호 → 앱 볼륨.
- 클리핑 방지를 끄고 이득이 풀스케일을 넘기면 잘리지 않고 피크 보호가 눌러 준다(음량이 그만큼 덜 커진다).

### 음량 분석 (태그 없는 곡)
ReplayGain 태그가 없는 곡은 사용자가 시작한 분석 작업이 직접 잰다. 파일은 읽기만 하고, 결과는 앱의 데이터베이스(`loudness` 표)에만 둔다.
- **측정**(`audio::loudness`): ITU-R BS.1770-4 / EBU R 128의 프로그램 음량. K 가중(1.7kHz 위 +4dB 하이 셸프, 38Hz 하이패스 — 아날로그 원형에서 샘플레이트마다 계수를 계산하므로 48kHz에서는 표준의 표와 같다),
  400ms 블록(75% 겹침), 절대 게이트 −70 LUFS, 상대 게이트 −10 LU. 이득 = −18 LUFS − 음량(ReplayGain 2.0의 기준). 피크는 샘플 피크다(트루 피크가 아니다. 샘플 사이 피크는 재생 때 피크 보호가 받는다).
  재생과 같은 스테레오 매핑을 거친 신호를 재므로 모노 파일은 양쪽 스피커에서 나는 소리로 계산된다.
- **앨범**: 트랙별 블록 에너지를 모아 앨범 전체를 하나의 프로그램으로 게이팅한다(트랙 값의 평균이 아니다). 앨범 값은 그 앨범의 모든 곡이 태그가 없고 모두 읽혔을 때만 만든다.
  곡이 200개를 넘는 "앨범"(낱개 파일 폴더)과 일부만 태그된 앨범은 곡 단위로만 잰다. 측정된 앨범에 곡이 새로 들어오면 앨범 전체를 다시 잰다(앨범 값이 달라지므로).
- **작업**(`library::loudness`): 코어 수의 절반(최대 4개)의 스레드로 디코드한다. 앨범 단위로 한꺼번에 저장하므로 중간에 멈춰도 반쯤 잰 앨범이 남지 않는다. 취소·종료 때는 읽던 파일에서 멈춘다.
  읽지 못한 파일은 세기만 하고 넘어간다. 자동으로 시작하지 않는다(곡을 끝까지 디코드하는 일이라 사용자가 정한 때에만 한다).
- **유효 범위**: 측정값은 파일의 한 상태(수정 시각·크기)에 속한다. 파일이 바뀌면 조인에서 빠져 읽히지 않고, 그 곡은 다시 분석 대상이 된다. 옮긴 파일(재연결)은 값이 따라간다.
- `library`가 `audio`에서 쓰는 것은 둘뿐이고 둘 다 장치와 무관하다: 여기의 `audio::loudness`(디코더와 측정기), 그리고 스캔이 AAC 파일에 대해 부르는 `audio::decoder::can_play`.
  후자는 파일을 열어 첫 패킷을 디코드해 보는 것으로, "AAC"라는 한 이름 아래 재생되는 것(스테레오 AAC-LC)과 안 되는 것(HE-AAC, 3채널 이상)을 가른다 —
  태그 라이브러리가 HE-AAC를 AAC-LC로 보고하는 경우가 있어 디코더에 묻는 것 말고는 확실한 방법이 없다. 거부된 파일은 "지원하지 않는 파일"로 센다.

### foobar2000과 견준 것
foobar2000의 기능 가운데 로컬 파일을 듣는 데 실제로 아쉬웠던 것을 넣었다: ReplayGain 스캐너에 해당하는 음량 분석(위, 단 파일에 쓰지 않는다), 검색 질의의 필드 지정(UX.md "검색"),
"현재 곡이 끝나면 정지", 곡 안에서의 건너뛰기. 넣지 않은 것과 이유:
- 태그 편집, 파일 이름 바꾸기·이동, 포맷 변환, CD 리핑, ReplayGain 태그 쓰기: OnEum은 음악 파일을 바꾸지 않는다(원본 보존이 검증 항목이다).
- 컴포넌트(플러그인), DSP 체인 편집, 화면 레이아웃·열 편집, 단축키 사용자 지정: 설정 없이 쓰는 앱이라는 방향과 맞지 않고, 플러그인은 안정성 경계를 무너뜨린다.
- 압축 파일 안의 곡, 크로스페이드: 후속 후보로 남긴다(PRD "범위 밖"). CUE 시트는 아래 "CUE 시트", 자동 플레이리스트는 스마트 플레이리스트로 넣었다.
- 인터넷 라디오·스트리밍, UPnP: 네트워크가 필요하다.

### 다른 플레이어들에서 가져온 것과 가져오지 않은 것
Apple Music, Swinsian, MusicBee, Plexamp, Doppler, Vox, Audirvana의 기능 소개를 놓고 고른 것: 잠자기 타이머, 스마트 플레이리스트(저장된 검색), 목록의 선택 열,
장르 둘러보기, 곡 메뉴의 앨범·아티스트 이동, 대기열을 플레이리스트로 저장. 구현 메모:
- 잠자기 타이머는 플레이어 스레드가 가진 시각 하나다. 마지막 5초는 엔진의 볼륨만 낮추고(`volume × 남은 시간 / 5초`) 사용자의 볼륨 값은 그대로 둔다. 시간이 되면 일시정지하고 엔진 볼륨을 되돌린다.
- 스마트 플레이리스트는 `settings.json`의 `(이름, 검색어)` 목록이다. 곡을 저장하지 않으므로 DB 스키마는 그대로이고, 내용은 검색 엔진이 그때그때 만든다.
  재생 횟수·즐겨찾기·추가·재생 시각 조건은 색인이 아니라 곡의 값으로 바로 확인한다(이 값들만 바뀐 스냅숏은 색인을 공유하므로 그래야 맞다).
- 장르 목록은 장르 보기를 열 때 스냅숏에서 만든다(대소문자만 다른 표기는 하나로, 한 곡의 여러 장르는 각각 센다).

가져오지 않은 것과 이유:
- 미니 플레이어, 전체 화면 "지금 재생 중" 보기, 데스크톱 위젯, 메뉴 막대 컨트롤러: 창 관리와 화면 설계를 새로 해야 하는 큰 일이라 후속 후보로 남긴다.
- 크로스페이드·Sweet Fades·자동 DJ 믹스: 곡 사이를 있는 그대로 잇는다는 원칙(gapless)과 반대 방향이다.
- 별점, 건너뛴 횟수: 즐겨찾기와 재생 횟수로 충분하다고 보았다. 별점은 파일 태그에 쓰는 관행이 있어 "파일을 바꾸지 않는다"와도 부딪친다.
- 태그 편집, 중복 곡 정리(삭제), 파일 정리: 음악 파일을 바꾸거나 지우지 않는다. 같은 곡의 다른 버전을 보여 주는 것까지만 한다.
- Last.fm 스크로블, 가사·표지 내려받기, 기기 동기화, 원격 조작, 스트리밍: 네트워크와 외부 서비스가 필요하다.
- 타이머로 컴퓨터를 끄거나 재우기: 시스템을 건드리는 일은 하지 않는다. 재생만 멈춘다.

### 2026-11-14에 가져온 것
- **파일 검사**(`audio::check`, `library::check`): 파일마다 한 번 끝까지 디코드한다(FLAC은 Symphonia의 MD5 검증을 켜고). 결과(판정, DR, 트루 피크)는 스키마 4의 `checks` 표에 파일의 수정 시각·크기와 함께 넣어, 파일이 바뀌면 읽히지 않는다(음량 분석과 같은 방식). 판정: 끝까지 디코드되고 MD5가 맞으면 "확인됨", MD5가 없으면 "디코드됨", 디코드 오류·MD5 불일치·길이가 정확한 형식(FLAC·ALAC·PCM·DSD)에서 1/100초 넘게 짧으면 "손상". MP3·AAC의 길이는 추정일 수 있어 잘림을 손상으로 보지 않는다.
  DR은 3초 블록, 블록 RMS(√2배) 상위 20%, 두 번째로 큰 블록 피크. 트루 피크는 44.1·48kHz에서 4배, 88.2·96kHz에서 2배 오버샘플(위상당 12탭 Kaiser), 둘러싼 샘플로는 지금까지의 피크를 넘을 수 없는 구간은 계산하지 않는다.
- **긴 곡 이어 듣기**: 플레이어가 곡을 새로 시작할 때(재생, 다음·이전 곡, 대기열에서 고르기 — gapless로 넘어갈 때는 아님) 20분 넘는 곡이면 저장된 위치(`resume_points` 표)에서 시작한다. 위치는 곡을 떠날 때와 세션을 저장할 때 적고, 끝까지 들으면 지운다.
- **앨범 단위 셔플**: 대기열이 트랙→앨범 키를 묻는 함수를 받아, 섞을 때 같은 앨범의 곡을 한 덩어리(대기열 순서 그대로)로 섞는다. 세션을 복원할 때는 순서를 다시 섞지 않는다.
- **고정**은 `settings.json`의 목록, **폴더 보기**는 스냅숏의 경로로 만든 곡 목록(경로 순)과 하위 폴더 단추, **통계**는 `history` 표를 별도 스레드에서 읽어 스냅숏과 합쳐 만든다(`library::stats`).
- **Apple Music 가져오기**(`library::apple`): XML 속성 목록을 직접 읽는다(의존성 추가 없음, 크기 1GiB·중첩 64단계 제한). 곡은 파일 위치로 찾고(NFC로도), 재생 횟수는 큰 쪽·마지막 재생은 늦은 쪽·추가일은 이른 쪽을 한 트랜잭션으로 합친다.
- **Windows의 주 스레드 작업**: `run_on_main`은 숨은 메시지 전용 창에 메시지를 보내 주 스레드에서 실행한다. 미디어 컨트롤 갱신이 주 스레드의 세션에 닿게 하려는 것이다.

### CUE 시트
- **곡의 경로**: 시트의 곡은 `<시트>.cue/<NN>`이라는 가상 경로로 식별한다(`library::cue::track_path`). DB·스냅숏·플레이리스트·재생 기록은 곡을 경로로 알아보므로 스키마는 바뀌지 않는다.
  `cue::resolve`가 경로를 오디오 파일과 구간(CD 프레임, 1/75초)으로 푼다. 파일 하나를 가리키는 시트만 쓴다. 시트가 고른 파일 이름은 이름만 쓰고(경로는 따라가지 않는다) 같은 폴더의 목록에서 찾으며, 없으면 같은 이름의 다른 오디오 확장자를 받는다. 대소문자와 유니코드 형태(NFC·NFD)는 가리지 않고 찾되, 경로는 폴더의 철자로 돌려준다(적힌 이름의 보통 파일이 있으면 `canonicalize`가 주는 이름으로, 폴더를 읽지 않고; 없거나 링크이면 폴더 목록에서): 다른 시스템에서 쓴 시트가 `abbey road.wav`라고 적거나 조합형 한글을 담고 파일 이름은 분해형이어도, 스캔이 만나는 경로와 같아야 그 파일을 "덮인 파일"로 알아본다. 적힌 철자 그대로인 파일이 먼저. 파일을 살펴볼 수 없으면(권한, 입출력 오류) "없음"이 아니라 "모름"이다(`cue::audio_of_checked`의 `Err`). 시트 크기는 1MiB까지, 글자는 M3U와 같은 해석(UTF-8·UTF-16·CP949).
- **스캔**: 걷기(WalkDir)가 폴더마다 `.cue`를 먼저 내놓도록 정렬해, 시트를 읽어 그 파일을 "덮인 파일"로 적은 뒤 그 파일이 나오면 따로 넣지 않는다(폴더 목록을 따로 한 번 더 읽지 않는다). 오디오 파일이 없거나 재생하지 않는 형식(`.ape` 등)이면 같은 이름의 재생하는 파일을 찾는다.
  시트의 곡의 크기는 오디오 파일의 크기, "수정 시각"은 오디오 파일의 것에 그 곡의 구간(시작·끝)으로 만든 표시를 섞은 값이다(`cue::stretch_stamp`). 그래서 파일이 바뀌거나 시트가 그 곡의 구간을 옮기면 그 곡의 음량 측정·검사 결과가 무효가 되고, 시트의 이름만 바뀌면 그대로 남는다.
  시트의 곡은 오디오 파일 안에 있는 것만이다: 파일의 끝보다 뒤에서 시작하는 곡(더 긴 리핑의 시트)은 곡이 아니고, 곡은 길어야 파일의 끝까지다(스캔의 길이와 디코더의 구간 모두). 파일의 길이를 모르면 다음 곡의 시작을 그대로 쓰고, 마지막 곡은 길이를 모르는 곡(0)으로 둔다. 곡이 하나도 파일 안에 없는 시트(다른 디스크의 시트)는 그 파일의 시트가 아니다: 파일을 그대로 한 곡으로 넣는다.
  시트가 가진 곡은 그 시트를 읽은 기록이 말한다(아래): 기록이 걷기가 본 그대로의 시트·파일에 대한 것이면, 기록에 없는 번호의 곡은 그 시트의 곡이 아니다(파일이 짧아져 끝 뒤에서 시작하게 되었거나, 파일만 들어가게 된 경우). 그런 곡이 라이브러리에 있으면 마무리에서 누락으로 처리한다. 읽은 것이 이번 스캔이든 전의 스캔이든(그 스캔이 취소되었거나 읽지 못한 폴더가 있어 마무리까지 가지 못했어도) 같다. 즐겨찾기라 "사용할 수 없음"으로 남은 곡은 그 뒤 걷기가 보지 않는다.
  시트가 바뀐 것(이름만 바뀐 것 포함)은 따로 기록한다: 곡들을 읽어 들인 시트의 수정 시각, 그때 나온 곡의 번호들, 오디오 파일의 수정 시각과 크기를 `kv` 표의 `cue_sheets_read`에 두고, 시트나 파일의 수정 시각이 그와 다르거나 그때 나온 곡 중 라이브러리에 없는 것이 있으면(곡을 라이브러리에서 지운 경우) 그 시트의 곡을 다시 읽는다. 번호를 두는 것은 파일 끝 뒤의 곡이 곡이 되지 않기 때문이다: 그런 시트를 스캔마다 다시 읽지 않고, 라이브러리가 그런 곡을 아직 가지고 있으면(즐겨찾기라 "사용할 수 없음"으로 남긴 것) 걷기는 그 곡을 보지 않는다(다시 "재생 가능"으로 바꾸지도, 그 때문에 시트를 다시 읽지도 않는다). 곡이 0이었던 시트는 같은 시트·같은 파일인 동안 파일을 덮지 않아, 그 파일은 보통 파일로 다뤄진다. 음악 폴더를 빼면 그 아래 시트의 기록도 지운다. 기록은 곡들이 실제로 저장된 뒤에만 남기고(읽기에 실패하면 다음 스캔이 다시 읽는다), 전체 스캔에서 만나지 못한 시트의 기록은 지운다. 같은 번호가 시트에 두 번 나오면 뒤의 것은 버린다(라이브러리는 시트의 곡을 번호로 알아본다).
  오디오 파일은 한 번만 읽어(속성·태그·표지) 곡마다 시트의 값으로 덮는다. 시트의 ReplayGain은 `REM REPLAYGAIN_*`, 파일의 RG 태그는 앨범 값으로만 쓴다. 다시 읽은 곡의 파일 상태(크기·"수정 시각")가 같으면 메모리의 측정값·검사 결과도 그대로 둔다(일반 파일도 같다).
  시트가 생기기 전의 파일 자체의 행, 같은 파일을 가리키는 두 번째 시트(이름순)의 곡은 그 자리를 대신하는 시트의 곡이 실제로 라이브러리에 들어왔을 때만 빠진다(오디오 파일을 읽지 못해 곡이 나오지 않았으면 그대로 둔다). 빠질 때 사용자가 준 것은 넘겨준다(`Db::hand_over_track`, 한 트랜잭션): 플레이리스트의 자리마다 시트의 곡들이 순서대로 들어가고, 즐겨찾기였으면 그 곡들이 즐겨찾기가 된다. 파일은 시트의 모든 곡에, 두 번째 시트의 곡은 첫 시트의 같은 번호 곡에 넘긴다. 그래서 즐겨찾기나 플레이리스트에 있던 파일이 "사용할 수 없음"으로 남지 않는다. 넘겨받는 곡은 시트의 지금 읽기가 주는 곡만이다(라이브러리가 남겨 두기만 한 옛 곡에게 넘기고 파일을 지우지 않는다). 넘겨받을 같은 번호의 곡이 없는 두 번째 시트의 곡은, 첫 시트를 지금 그대로 읽은 기록이 있으면 누락으로 처리한다.
  한 파일에 시트가 둘이면 이름순으로 첫 시트가 그 파일을 가진다(`WalkResult::claimed`). 첫 시트의 곡이 하나도 파일 안에 없어 파일만 들어가는 경우에도 그렇다: 두 번째 시트는 쓰지 않는다(스캔할 때마다 결과가 바뀌지 않도록).
  시트의 곡이 "없어졌다"는 것은 시트가 없거나, 읽은 시트가 쓸 수 없는 내용이거나, 그 번호가 없거나, 오디오 파일이 없을 때다(`file_is_gone`). 시트나 그 오디오 파일을 **살펴보지 못한** 것(권한, 입출력 오류)은 없어진 증거가 아니라서 그 곡들을 그대로 두고, 그동안 그 오디오 파일을 한 곡으로 따로 넣지도 않는다: 어느 파일인지는 시트를 읽어야 알므로 크기로 알아본다(`hold_sheet`): 기록에 있는 파일 크기(기록이 없으면 그 곡들이 기록한 크기)와 같은 크기의 새 오디오 파일을 같은 폴더에서 건너뛰고, 그 파일을 가리키는 다른 시트도 그동안 쓰지 않는다.
  시트의 곡의 폴더는 시트의 폴더다: 앨범 키(앨범 아티스트가 없을 때 폴더로 가르는 것, `CD1`·`CD2`를 한 앨범으로 묶는 것)와 태그가 엇갈린 앨범 합치기도 그렇게 본다.
  음악 폴더가 "전에 스캔한 그 폴더"인지의 증거(아는 파일이 하나라도 그 자리에 있는가)에는 시트가 새로 덮은 아는 파일, 아직 있는 시트, 시트가 사라진 뒤 같은 폴더에서 같은 크기로 다시 나온 오디오 파일도 넣는다. 그렇지 않으면 앨범 하나뿐인 음악 폴더에서 시트를 더하거나 지울 때 폴더 전체를 "다른 드라이브"로 보고 곡을 "사용할 수 없음"으로 남겼다.
  폴더가 의심 상태(`unconfirmed_after`)인 것은 그 전부터 있던 곡에 대한 것이다. 그 뒤에 들어온 곡은 그 뒤의 폴더에서 찾은 것이므로, 그 뒤에 알게 된 파일이 하나라도 그 자리에 있으면 그중 없어진 것은 없어진 것으로 처리한다(전에는 의심이 풀리지 않는 한 지운 파일이 모두 "사용할 수 없음"으로 남았다).
- **재생**: `TrackDecoder`가 구간을 가지고 시작 프레임으로 정확히 탐색해 끝에서 자른다(`info`의 길이·탐색 위치도 구간 기준). 프레임→샘플은 `rate × frame / 75`라 44.1·48kHz 계열에서 정확하다. 이어지는 곡은 같은 파일의 이어진 구간이라 gapless 미리 열기에서 샘플 단위로 이어진다. 메모리 재생은 파일 전체를 올리고 구간을 적용하며, 다음 곡이 같은 파일의 곡이면 메모리의 그 파일을 함께 읽는다(`FileInMemory::share`: 한 번 읽고 예산에도 한 번 센다).
  구간의 끝은 패킷 시각으로 잰 위치로 자른다(디코드한 양을 세면, 손상된 패킷을 건너뛴 만큼 다음 곡으로 넘어가 버린다). DSD는 건너뛸 패킷이 없어 센다.
  검사·음량 분석도 같은 디코더라 곡의 구간만 잰다. FLAC MD5는 파일 전체의 값이라 시트의 곡에는 대조하지 않는다(`checksum_matches`가 `None`).
- **나머지**: `.cue`의 변화도 그 폴더의 증분 스캔을 부른다. 곡이 디스크에서 무엇인지는 `Track::file()`(아무것도 읽지 않음: 시트의 곡이면 시트)과 `Track::audio_file()`(읽을 오디오 파일)로 묻는다. 폴더 보기, "앨범 제목이 없을 때 폴더 이름", 표지 재생성의 폴더 그림은 앞의 것을, Finder에서 보기(화면 스레드가 아닌 곳에서 시트를 읽는다)·표지 재생성의 내장 그림·곡 정보의 크레딧은 뒤의 것을 쓴다. 재생·검사·음량 분석은 곡을 열 때 시트를 한 번만 읽어 파일과 구간을 함께 얻는다(`TrackDecoder::open_located`). 시트가 있는 음악 폴더의 오디오 파일을 따로 열면(Finder, 플레이리스트) 그 시트의 곡들을 연 것으로 친다(시트를 지금 읽을 수 없으면 스캔과 같이 기록의 파일 크기로 그 시트의 파일임을 알아본다; 그 곡들이 "사용할 수 없음"이면 다시 쓸 수 있게 한다: 파일이 있으므로): 그 파일을 한 곡으로 넣으면 다음 스캔이 시트의 곡으로 바꾸며 지운다. 시트의 곡에는 그 파일에 든 가사를 쓰지 않는다(앨범 전체의 가사이므로). 통계의 라이브러리 크기는 시트 하나의 파일을 한 번만 센다.
  M3U8로 내보내면 시트의 곡은 OnEum의 경로(`앨범.cue/02`)로 적힌다: M3U에는 파일의 한 구간을 가리키는 표준 방법이 없다. 그 경로를 가져올 때는 시트를 찾아 곡을 등록한다(`import_paths`): 음악 폴더 안의 시트면 그 폴더의 곡으로, 밖이면 따로 등록한 곡으로(이 곡들은 따로 등록한 파일을 확인할 때 시트 단위로, 시트를 읽은 기록으로 바뀐 것을 알아본다: `scan::check_loose_sheet`). 그래서 내보낸 플레이리스트를 음악 폴더를 아직 넣지 않은 라이브러리에서도 되살릴 수 있다.
- **하지 않은 것**: 여러 파일을 가리키는 시트(곡마다 파일이 있으니 파일을 그대로 쓴다), 첫 곡의 `INDEX 01` 앞에 숨은 곡(HTOA), 시트의 `PREGAP`·`INDEX 00`(곡 사이 간격은 다음 곡의 `INDEX 01`까지 앞 곡에 붙는다). 데이터 트랙은 건너뛴다.

### 가사와 크레딧
- 가사(`library::lyrics`): 태그(Lyrics/UnsyncLyrics)나 같은 이름의 `.lrc`·`.txt`. 시간 표시(`[mm:ss.xx]`, 한 줄에 여러 개, `[offset:]`, 낱말 단위 표시)가 두 줄 이상이면 싱크 가사로 보고 시간순으로 정렬해 둔다.
  화면은 재생 위치로 지금 줄을 찾아 강조하고, 줄이 바뀐 다음 프레임에 그 줄이 보이게 스크롤한다. 줄을 누르면 그 시각으로 탐색한다.
- 크레딧·작품 정보(`library::details`): 곡 정보 패널을 열었을 때 그 파일의 태그에서 읽는다(DB에 넣지 않는다 — 스키마와 스캔 시간을 늘리지 않으려고). 한 번에 한 곡만 백그라운드로 읽는다. 스캔과 같은 제한으로 읽는다(일반 파일만, 읽는 양 256MB·읽기 호출 10만 번까지, 해석기 패닉은 막음, 표지는 읽지 않음).
- 다른 버전: 제목과 아티스트를 정규화해 같은 곡을 스냅숏에서 찾고, 무손실·샘플레이트·비트 깊이 순으로 여섯 개까지 보여 준다.

### 옛 한국어 인코딩
유니코드 이전에 한국어 Windows에서 만든 파일은 글자를 시스템 코드 페이지(CP949, EUC-KR의 확장)로 담고 있으면서 그렇다고 밝히지 않는다:
ID3 태그는 "Latin-1"이라고 선언하고, `.lrc`·`.m3u`는 아무것도 선언하지 않는다. `library::legacy`가 이를 알아보고 바로 읽는다.
- **알아보기**(순수 함수, 엄격하게): ASCII가 아닌 모든 바이트가 올바른 2바이트 글자의 일부여야 하고, 그 가운데 KS X 1001의 한글 음절(첫 바이트 0xB0~0xC8, 둘째 0xA1 이상)이
  하나 이상 있어야 한다. 서양어에서 이 조건이 되려면 특정 범위의 악센트 글자 둘이 연달아 와야 하므로 Beyoncé, Motörhead, Déjà Vu 같은 제목은 걸리지 않는다(단위 테스트의 목록).
- **변환**: 운영체제에 맡긴다(macOS `CFStringCreateWithBytes`의 `kCFStringEncodingDOSKorean`, Windows `MultiByteToWideChar(949)`). 변환 표를 앱에 넣지 않는다.
- **적용**: 태그 값(`tags::clean`), 태그 속 가사, 가사 옆 파일, 가져오는 플레이리스트. 파일은 UTF-8 → UTF-16(BOM) → CP949 순으로 본다.
- **이미 스캔된 곡**: 저장된 제목·아티스트·앨범·장르가 "지금 읽으면 달라질" 글자이면(`tags::would_read_differently`) 파일이 바뀌지 않았어도 다음 스캔에서 다시 읽는다.
- 한국어 이외의 옛 코드 페이지(Shift-JIS, GBK 등)는 다루지 않는다.

## 재생 상태
`Idle → Loading → Playing ⇄ Paused`, `Seeking`(재생/일시정지 상태를 유지한 채 위치 이동),
`Ended`(대기열 끝), `Error`(복구 가능한 오류, 메시지 포함). 전이는 Player 스레드에서만 일어난다.

## 라이브러리와 저장
- **SQLite**(`library.db`, WAL): roots, tracks, playlists, playlist_items, history, queue, kv, loudness(스키마 3: 앱이 측정한 음량, 곡의 수정 시각·크기와 함께).
  스키마 버전은 `PRAGMA user_version`. 업그레이드는 처음부터 쓰기 잠금을 잡는 트랜잭션 하나(`BEGIN IMMEDIATE`)로 하고, 실패하면 롤백만 한다(열려 있는 다른 연결 밑에서 파일을 바꿔치기하지 않는다).
  그 전에 `VACUUM INTO`로 WAL까지 담긴 일관된 사본을 `library.db.bak-v<버전>`에 남긴다(사본과 잠금 사이에 다른 연결이 커밋했으면 다시 만든다).
  재생 세션(대기열과 현재 곡·위치)은 한 트랜잭션으로 저장하고, 성공했을 때만 플레이어가 변경 표시를 지운다. 플레이리스트의 통째 교체(실행 취소)와 곡이 든 새 플레이리스트도 한 트랜잭션이다.
  손상된 DB는 옆으로 치우고 새로 만든 뒤 사용자에게 알린다.
- **제거한 곡**(스키마 6, `removed_files`): 곡을 라이브러리에서 제거하면 행을 지우는 것과 같은 트랜잭션에서 그 파일의 경로를 적는다(`Db::delete_tracks_remembering`). 제거는 파일을 건드리지 않으므로, 적어 두지 않으면 그 폴더의 다음 스캔(시작할 때마다)이 같은 파일을 새 곡으로 다시 넣는다. 목록은 메모리에도 있고(`Inner::removed`) 스캔이 세 곳에서 본다: 모르는 파일을 만났을 때 건너뛰고(`scan::walk`), CUE 시트의 트랙이 빠져 있어도 시트를 다시 읽을 이유로 치지 않으며(`walk_sheet`, `record_sheets_read`), 다시 읽은 시트가 내놓은 트랙 가운데 제거된 것은 넣지 않는다(`commit_scanned`). 앱 폴더나 연결한 폴더의 경로가 바뀌면 곡의 경로와 함께 옮긴다(`rewrite_below`). 목록에서 빠지는 때: 그 파일을 직접 열었을 때(`import_paths`), 설정의 "제거한 곡 되돌리기"(`Library::restore_removed`), 폴더를 라이브러리에서 뺐을 때, 폴더 전체 스캔 뒤 그 파일이 디스크에 없을 때.
- **메모리 인덱스**: 모든 곡의 표시용 메타데이터와 정규화된 검색 문자열을 불변 스냅숏으로 보관한다.
  검색·정렬·앨범 묶기는 스냅숏에서 수행하고 표는 보이는 행만 그린다. (5만 곡 기준 메모리·속도는 TESTING.md)
- **검색 정규화**: NFKC → 소문자. 초성 문자열을 따로 만들어 초성 검색에 쓴다. 원본 경로·태그는 그대로 보존한다.
  일반 검색어는 네 필드를 이어 붙인 문자열 하나를 훑고(가장 긴 단어로 후보를 추린 뒤 나머지를 확인), `필드:값` 조건은 그 후보에 대해 곡별 정규화 문자열·연도·코덱으로 확인한다.
- **앨범 식별**: 앨범 제목 + (앨범 아티스트 | 컴필레이션 표시 | 폴더). 앨범 아티스트가 없으면 폴더로 구분해
  같은 제목의 다른 앨범이 합쳐지지 않게 한다(`CD1`/`Disc 2` 폴더는 상위 폴더로 본다).
  한 폴더 안에서 같은 제목인데 일부 파일에만 앨범 아티스트 태그가 있으면, 태그된 앨범이 정확히 하나일 때에 한해 표시 단계에서 합친다.
- **누락·분리**: 루트 폴더가 없으면(외장 드라이브 분리) 그 아래 곡을 "사용할 수 없음"으로 표시만 하고 지우지 않는다.
  루트는 있는데 파일이 없으면: 같은 크기·같은 태그의 새 파일이 있으면 경로를 바꿔 재연결하고,
  없으면 플레이리스트·즐겨찾기에 쓰인 곡은 누락으로 남기고 나머지는 라이브러리에서 뺀다.
- **파일 감시**: FSEvents(notify). 이벤트를 2초 묶어 해당 폴더만 증분 스캔한다. 이벤트 유실 표시를 받으면 전체 재스캔.
  감시기를 만들지 못하면 30초마다 다시 시도한다. 감시하지 못하는 폴더는 5분마다(iPhone에서는 감시기를 쓰지 않고 30초마다 — 아래 "iPhone" 표), 감시하는 네트워크 공유의 폴더(다른 컴퓨터에서의 변경은 파일 이벤트로 오지 않는다)는 30분마다 다시 스캔한다 — 스캔은 공유 전체를 훑고 그 컴퓨터의 디스크를 깨우므로 드물게. 감시가 다시 서면 한 번 더 스캔한다.
  폴더를 감시하기 시작한 직후에는 시스템의 이벤트 스트림이 아직 돌지 않는다(재 보니 수백 ms, 때로 1.5초 넘게). 그 사이의 변화는 누구도 알려 주지 않으므로, 감시를 시작한 폴더는 스트림이 자리 잡을 시간(3초)이 지난 뒤 한 번 더 스캔한다(`Timing::watch_settle`, 다음 확인 주기에 요청되므로 5~10초 뒤). 바뀐 것이 없으면 파일을 읽지 않는 스캔이다.
  라이브러리의 알림은 진행 상황이 대부분이므로, 플레이어는 곡이 라이브러리에서 빠졌을 때(`Library::removals`가 바뀌었을 때)만 대기열을 다시 확인한다.
- **앨범 이미지**: 내장 이미지(없으면 폴더의 cover/folder 이미지)를 최대 600px JPEG으로 줄여 Caches에 저장.
  입력은 20MB·4천만 화소로 제한. 캐시는 512MB를 넘으면 오래된 것부터 지운다.
- **경로**: `~/Library/Application Support/OnEum/`(DB, 설정), `~/Library/Caches/OnEum/`(이미지), `~/Library/Logs/OnEum/`.
- **설정**: `settings.json`. 임시 파일에 쓰고 rename하는 원자적 저장. 저장 여부는 창 크기를 아는지와 무관하다(Android는 창 크기를 알려 주지 않는다. 한때 그 때문에 Android에서는 아무 설정도 저장되지 않았다). 쓰는 곳이 셋이라(저장 스레드, 그 스레드가 없을 때의 직접 쓰기, 휴대폰에서 화면을 떠날 때) 쓰기마다 순번을 받고(`storage::settings::take_turn`), 더 늦은 순번이 이미 쓰였으면 쓰지 않는다(`write_atomic_in_turn`): 먼저 시작된 옛 내용이 뒤늦게 새 내용을 덮지 않는다. 실패하면 저장 안 된 상태로 두고 10초 뒤 다시. 8MB를 넘거나 해석되지 않는 파일은 `.corrupt`(이미 있으면 `.corrupt-2`, `-3` …)로 치우고 기본값으로 시작한다. 있는데 읽지 못하는 파일(다른 프로그램이 잠시 잠근 경우 등)은 0.2초 간격으로 세 번 시도하고, 그래도 안 되면 `.unreadable`로 치운 뒤 기본값으로 시작한다(나중의 저장이 그 내용을 덮지 않게). 목록(스마트 플레이리스트, 보정 프로필, 프리셋)은 항목별로 읽어 못 읽는 항목만 뺀다.
- 데이터·캐시·로그 폴더는 0700으로 만든다(경로·재생 기록이 다른 사용자에게 보이지 않게).

## macOS 통합
- 메뉴: muda. 편집 메뉴 액션은 `responder` 브리지로 egui에 전달(ADR 0001).
- `application:openURLs:`와 `applicationShouldHandleReopen:`은 winit 앱 델리게이트 클래스에 런타임으로 추가한다.
- Now Playing: `MPNowPlayingInfoCenter`, 미디어 명령: `MPRemoteCommandCenter`. 핸들러는 Player 채널로 `Command`를 보낸다.
  이번 실행에서 실제로 재생을 시작하기 전에는 Now Playing을 게시하지 않는다(실행만으로 다른 앱의 미디어 키를 빼앗지 않기 위해).
  실행 후 3초 안에 들어온 원격 "재생" 명령은 무시한다(실행 직후 자동으로 소리가 나지 않게).
- 창이 가려져 UI 프레임이 멈춰도 Now Playing 갱신은 메인 큐 작업으로 수행하므로 영향이 없다.
- 배포: 샌드박스 없는 직접 배포(.dmg). Hardened Runtime은 Developer ID 서명 시 켠다. 마이크·전체 디스크 접근 권한을 요구하지 않는다.

`platform` 모듈이 시스템별 구현을 같은 이름(`finder`, `menu`, `nowplaying`, `device` …)으로 내보낸다. 호출하는 쪽에는 `cfg`가 없다(경로와 글꼴처럼 값만 다른 곳 제외).

|---|---|---|

| 파일 위치 보기 | Finder | 파일 탐색기 |

| 잠자기 전 일시정지 | 알림을 받아 처리 | 없음(장치가 사라지면 스트림 무효화로 처리) |

### iPhone
같은 crate를 `aarch64-apple-ios`(기기)와 `aarch64-apple-ios-sim`(시뮬레이터)으로 빌드한다. 결정과 그 근거는 [adr/0002-iphone.md](adr/0002-iphone.md).

| 항목 | iPhone |
|---|---|
| 화면 | `ui::phone`. `platform::PHONE`이 참이면 폰 화면을 그린다. `ONEUM_PHONE=1`로 Mac의 창에서도 같은 화면을 볼 수 있다(개발용) |
| 창 | 씬 생명주기가 필수다(iOS 27). winit은 씬을 모르므로 앱의 씬 델리게이트(`OneumSceneDelegate`, Info.plist에 등록)가 winit의 창을 씬에 넣는다 |
| 그리는 크기 | winit 창의 `safeAreaInsets`를 0으로 돌려주게 해서 표면과 배치를 화면 전체로 맞추고, 실제 여백은 앱이 egui에 넘긴다(`raw_input_hook`) |
| 메뉴·단축키 | 없음. 메뉴가 하던 일은 화면의 버튼과 시트가 한다. 외장 키보드의 키는 받지 않는다(winit 0.30은 iOS에서 글자 입력만 넘겨준다) |
| 음악의 위치 | 앱의 Documents 폴더(첫 실행 때 음악 폴더로 등록). 파일 앱과 Finder의 파일 공유에 보인다(`UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`). 그 밖에 "폴더 연결"로 고른 바깥 폴더(아래) |
| 파일 고르기 | 문서 선택기(`platform::files`). 음악 파일은 사본을 받아 `Documents/Imported`로 옮기고, 폴더는 접근 권한을 얻어 `Documents` 아래로 복사한다. 내보내기는 임시 폴더에 쓴 뒤 저장 위치를 고르게 한다. `PickKind::FolderInPlace`는 복사하지 않고 그 폴더의 경로를 돌려준다 |
| 파일 열기 | 씬 델리게이트의 `scene:openURLContexts:`. 컨테이너 밖의 파일은 가져온 뒤에 연다 |
| 보관 공간 이동 | 업데이트·복원으로 컨테이너 경로가 바뀌면 `Db::follow_home`이 음악 폴더·곡·CUE 시트 기록의 경로를 새 위치로 옮긴다(한 트랜잭션). `Library::open_in_home` |
| 바깥 폴더 연결 | 문서 선택기로 고른 폴더는 앱이 도는 동안 읽을 수 있고, 그때 만든 북마크로 다음 실행에서 권한을 되찾는다(`platform::ios::files`: `link`, `restore_linked_folders`, `reach_linked_folders`, `forget_linked_folder`; 북마크는 데이터 폴더의 `linked-folders.json`). 보관함을 열기 전에 되찾으며, 북마크가 알려 준 위치가 전과 다르면(폴더를 옮기거나 이름을 바꿈) `Db::follow_folder`가 그 음악 폴더와 곡의 경로를 새 위치로 옮긴다(`Library::open_following`). 폴더를 라이브러리에서 빼면 북마크도 지운다. 데스크톱에서는 같은 이름의 함수가 아무 일도 하지 않는다 |
| 소리 | 오디오 세션을 재생용으로 두고 스트림을 열기 전에 활성화한다. 출력 장치 선택과 독점은 없다(`DEVICE_CONTROL` 거짓). 샘플레이트는 맞출 수 있다(`RATE_CONTROL` 참): `platform::ios::device`가 데스크톱의 `AudioDevice`와 같은 모양으로 세션의 `sampleRate`를 읽고 `setPreferredSampleRate`로 요청한 뒤 세션이 따라오는지 0.7초까지 기다린다. cpal은 세션의 샘플레이트로 스트림을 열므로, 세션이 따라오지 않으면 엔진이 평소처럼 변환한다 |
| 끊김과 경로 변경 | 끊김이 시작되면 일시정지, 끝나고 시스템이 허락하면(그리고 우리가 멈춘 경우에만) 재생. 출력이 사라지면(이어폰 분리) 일시정지 |
| Now Playing | macOS와 같은 코드(`platform::apple::nowplaying`). 표지의 이미지 타입과 재생 상태 알림만 다르다 |
| 백그라운드 | 재생은 이어진다(오디오 백그라운드 모드). 화면은 다시 그리지 않는다(`lifecycle::in_foreground`). 돌아올 때 폴더를 다시 읽는다 |
| 폴더 감시 | 감시기(`notify`)를 쓰지 않는다: iOS에서 notify는 kqueue로 파일과 폴더마다 핸들을 열어 두므로(504곡에서 열린 파일 652개) 곡이 많으면 프로세스의 한도를 넘는다. 대신 앱이 앞에 있는 동안 30초마다 음악 폴더를 다시 스캔한다(`library::watch`의 `POLLED_ONLY`, `Timing::file_events`; 바뀐 것이 없으면 파일을 읽지 않는 스캔). 앱이 앞으로 올 때와 가져온 뒤에도 스캔한다 |
| 메모리 재생 | 상한 256MB |
| 글꼴 | San Francisco(`/System/Library/Fonts/Core/SFUI.ttf`) + 시스템 한글 글꼴 |
| 화면 모드 | 씬의 값을 읽어 egui에 넘긴다. 앱에서 고른 모드는 창에 지정해 상태 표시줄과 시스템 시트가 따른다 |
| 화면 방향 | 세로와 가로(`UISupportedInterfaceOrientations`). 배치는 화면의 크기와 안전 영역에서 정해진다: 폭이 높이보다 넓으면 플레이어는 표지를 왼쪽에 조작부를 오른쪽에 두고, 재생 중인 곡의 막대는 탭과 한 줄을 나눠 쓴다. 시트는 520pt보다 넓어지지 않는다 |
| 사용 안내 | `USER_GUIDE_IOS.md`, `USER_GUIDE_IOS.en.md` |
| 번들 | 시뮬레이터: `scripts/ios-sim.sh`가 직접 묶는다. 기기: `ios/OnEum.xcodeproj`가 cargo로 만든 실행 파일을 넣고 서명한다. Info.plist는 하나(`ios/Info.plist`) |

### Android
같은 crate를 `aarch64-linux-android`용 공유 라이브러리(`liboneum.so`)로 빌드하고(`cargo rustc --lib --crate-type cdylib`, crate의 종류는 다른 시스템을 위해 그대로 둔다), 얇은 Java 껍데기(`android/`)와 함께 APK로 묶는다. 계획과 실제로 달라진 점은 [ANDROID_PLAN.md](ANDROID_PLAN.md).

| 항목 | Android |
|---|---|

Android의 창은 한 방식만 쓸 수 있으므로(Vulkan 표면이 있으면 EGL이 "already connected to another API"로 거절당한다) 먼저 쓸 방식이 정해지면 그 방식만 준비한다. 기본이 아닌 방식은 시험 삼아 쓴다(`app::relaunch::begin_trial`): 시작할 때 `graphics-trying.txt`를 두고 3초 뒤 프레임이 그려졌으면 지운다. 다음 실행이 그 파일을 보면 지난 실행이 얼마 못 간 것이므로 기본 순서로 돌아가고 선택을 자동으로 되돌린다. 네 번째 선택 `glow`(시험, 2026-11-16)는 wgpu 대신 eframe의 glow 렌더러를 쓴다(`eframe::Renderer::Glow`, Android 타깃에서만 `glow` 기능을 켠다; egui_glow + glutin의 EGL). 이때는 wgpu 장치가 없어 장치 감시(`renderer::watch`)와 그래픽 메모리 읽기가 비고, 그리는 장치의 이름은 GL의 `RENDERER`/`VERSION`에서 읽는다(`renderer::note_glow`). 디버그 이름을 붙이는 인스턴스 플래그는 끈다(에뮬레이터의 Vulkan 드라이버가 `SetDebugUtilsObjectName`에서 죽는다, `ui::renderer::instance_flags`) |
| 그래픽 장치를 잃었을 때 | 드라이버는 그리던 장치를 언제든 가져갈 수 있다(실제 폰에서 일어남). wgpu는 그 사실을 알리는 콜백을 달지 않으면 아무 말도 하지 않고 이후의 요청을 조용히 버리며, UI 라이브러리(egui-wgpu)는 다음 프레임에서 버퍼 쓰기가 비어 돌아오면 패닉한다. 그래서 `ui::renderer::watch`가 장치를 지켜본다: 잃음 콜백이 표시를 세우고, 잡히지 않은 오류는 앱을 끝내지 않고 로그에 `graphics:`로 남는다. 앱은 매 프레임을 그리기 직전에(`logic`의 끝) 표시를 보고, 섰으면 그리지 않는다(`graphics_lost`): 세션을 저장하고, 프로세스가 장치를 다시 만들 수 없으므로(eframe은 장치를 한 번 만든다) 새 프로세스로 다시 연다. `MainActivity.relaunch`가 별도 프로세스의 `RelaunchActivity`를 띄우고, 그것이 앱 프로세스가 저장을 마치고 끝나기를 기다렸다가(10초까지) 앱을 런처처럼 연다. 끝나는 실행은 `data/relaunch.txt`에 시각과 재생 중이었는지를 적고(`app::relaunch`), 새 실행이 그것을 읽어 이어 재생하고 알린다. 잃은 방식도 함께 적어(`lost_on`) 설정이 자동이면 다음 실행부터 다른 방식으로 그린다. 1분 안에 다시 잃으면 다시 열지 않고 시스템 알림(토스트)을 띄우고 끝난다. 같은 프레임 안에서 텍스처를 올리다 잃는 경우는 막지 못한다(표시를 볼 기회가 없다) |
| 그래픽 메모리 | 한 폰이 그래픽 메모리 부족으로 20초마다 끝났다(드라이버의 메모리 매핑 실패). 그래서 요구를 줄였다: wgpu의 할당기는 4 · 8MB 덩어리부터 쓰는 만큼 받는다(`MemoryHints::MemoryUsage`; 기본값은 64 · 128MB 덩어리를 받아 통째로 매핑해 둔다). 글자를 모아 두는 그림(글리프 아틀라스)은 UI 라이브러리가 장치의 최대 텍스처 폭으로 만들고 높이를 두 배씩 키우며 그때마다 전체를 다시 보내므로, 폰에서는 폭을 4096으로 줄여 알린다(`raw_input_hook`, `PHONE_GLYPH_PICTURE_SIDE`: 최대 64MB, 80% 차면 라이브러리가 비운다). 한글 글꼴은 글자당 한 벌만 보관하게 한다(`theme::korean_tweak`: 라이브러리는 한자·가나만 그렇게 하고 한글은 1/4픽셀씩 어긋난 네 벌까지 둔다). 무엇이 느는지는 `ui::memory`가 2초마다 읽는다: `/proc/self`의 매핑 수와 많은 이름, 가상·실제 크기, 할당기 보고(덩어리·조각), wgpu의 객체 수(`counters` 기능을 켜려고 `wgpu`를 직접 의존성으로 적었다), 글자 그림의 크기, 그린 프레임 수. 눈에 띄게 늘면 로그에 `memory:` 한 줄, 설정 → 정보에 지금 값, 지난 실행들의 마지막 줄은 오류 기록에 |
| 글꼴 | Roboto(`/system/fonts/Roboto-Regular.ttf`) + 시스템 한글 글꼴 |
| 화면 모드 | 시스템의 밝기 모드를 Java가 넘겨주고, 앱에서 고른 모드에 맞춰 상태 표시줄과 내비게이션 막대의 아이콘 색을 바꾼다 |
| 접근성 | 화면 낭독기(TalkBack)는 지원하지 않는다: eframe의 `accesskit` 기능은 Android의 NativeActivity에서 쓸 수 없어 Android 빌드에서만 뺀다 |
| 사용 안내 | `USER_GUIDE_ANDROID.md`, `USER_GUIDE_ANDROID.en.md` |
| 묶음 | `scripts/android-build.sh`가 라이브러리를 만들어 `android/app/src/main/jniLibs/arm64-v8a`에 두고 Gradle로 APK를 만든다(arm64 전용, minSdk 30). 릴리스 서명은 `ONEUM_ANDROID_KEYSTORE*` 환경 변수, 없으면 디버그 키 |

## 네트워크의 미디어 서버 (DLNA)
보관함과 별개의 길이다. 서버를 스캔하지 않고, 서버가 보여 주는 폴더를 그때그때 읽어(`upnp::browse`) 보여 주며, 재생한 곡만 대기열을 위해 기억한다.

- **통신** (`net`): 서버 찾기는 SSDP `M-SEARCH`(UDP)를 보내고 답의 `LOCATION`을 모은다. 찾는 동안만 소켓을 열고, 앱이 여는 포트는 없다(서버의 알림 구독을 하지 않음). 주소로 추가할 때는 그 호스트의 1900번 포트에 같은 질문을 직접 보낸다(네트워크 전체에 묻지 않으므로 iPhone에서도 된다). 장치 설명에서 ContentDirectory의 주소를 얻고 `Browse`(SOAP)로 폴더를 200개씩 읽는다(한 폴더 5,000개까지).
- **신뢰하지 않는 입력**: 장치 설명 1MB, `Browse` 답 8MB, 표지 16MB, 헤더 64KB, 연결 3초·읽기 10초, 리다이렉트 3번. XML은 깊이 64까지, DOCTYPE과 사용자 정의 엔티티는 풀지 않는다. 주소는 `http://`만 따른다. 음악 데이터는 파일과 같은 디코더 한도를 받는다.
- **곡의 정체** (`library::remote`): 서버의 곡은 보관함의 `tracks`가 아니라 `remote_tracks` 표에 있고 **음수 번호**를 쓴다(보관함의 곡은 양수). 대기열의 그 항목은 `remote_queue` 표에 같은 위치 번호로 저장한다(`queue.track_id`는 `tracks`를 가리키는 외래 키라 그대로 둔다). 앱을 열 때 저장된 대기열이 가리키지 않는 것은 지운다. 보관함의 목록·검색·통계·즐겨찾기·플레이리스트는 이 곡들을 보지 못하고(스냅샷에 없음), `Library::track`과 화면의 `track()`만 부호를 보고 찾아 준다. 화면의 보관함 전용 동작(즐겨찾기, 플레이리스트, 제거)은 `apply`에서 걸러 낸다.
- **곡의 위치**: 서버 곡의 주소(`http://…`)는 파일 경로가 다니는 자리(`Track::path`, `PlayableTrack::path`)에 그대로 실려 다니고 `model::http_address`가 둘을 가른다. 경로를 파일로 다루는 곳(CUE, 가사 옆 파일, Finder에서 보기)은 그 주소로는 아무것도 찾지 못해 조용히 넘어간다.
- **재생** (`audio::remote`): 메모리 재생의 "받는 대로 메모리에, 아직 안 받은 곳은 원본에서"(`audio::source`)를 원본이 파일이 아니어도 되게 넓혔다(`Origin`). 서버의 곡은 연결 하나로 차례대로 받아 메모리에 올리고(메모리 재생 설정과 무관하게, 상한 안에서), 디코더가 받은 곳보다 조금 앞을 읽으려 하면 받기를 기다린다. 멀리 건너뛸 때(탐색, 파일 끝의 표)는 그 자리부터 달라는 요청(Range)을 따로 보낸다. 서버가 부분 요청을 받지 않으면 받기를 기다린다. 메모리에 올릴 수 없는 곡(1GB 초과, 길이를 모름, 상한 초과)은 받는 대로 흘려 재생한다. 다음 곡이 서버의 곡이면 지금 곡이 다 올라온 뒤 미리 연결해 올린다(곡 사이에 네트워크를 기다리지 않게).
- **표지**: 서버가 준 주소에서 받아 보관함의 표지 캐시에 넣는다(주소당 한 번, 백그라운드).
- **하지 않는 것**: 음량 보정(서버의 곡에는 태그도 측정값도 없다), 가사, 파일 검사, 서버 안 검색, 하위 폴더까지 한꺼번에 재생.
