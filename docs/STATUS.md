## 남은 작업
1. Developer ID 인증서가 준비되면 docs/RELEASE.md 4~6절을 수행하고 결과를 TESTING.md에 기록.
2. docs/TESTING.md "검증 대기" 표의 수동 항목 확인(VoiceOver, 미디어 키, Bluetooth, 잠자기, 드래그 앤 드롭, 파일 패널).
3. 출력 품질 옵션을 실제 USB DAC에서 확인(비트 깊이 전환, 곡 사이 틈, 독점 중 다른 앱 소리의 행방)하고 옵션을 켠 채 장시간 재생.
4. 실제 FLAC 8곡은 확인함(TESTING.md "실제 음악 파일"). FLAC 외 포맷과 대규모 실제 라이브러리로 스캔·재생을 확인하고 발견되는 태그/코덱 문제를 기록.
5. 공개 배포 전 라이선스 전문 묶음 추가(RELEASE.md 7절).
6. Windows판을 실제 Windows에서 실행해 docs/TESTING.md "Windows"의 미확인 항목을 확인하고, 그 뒤에 지원 환경으로 적는다. 2026-11-14의 시작 오류 수정이 효과가 있었는지가 먼저다(안 되면 오류 창의 내용이나 `%LOCALAPPDATA%\OnEum\Logs\oneum.log`).
7. 음량 보정을 귀로 확인한다: `dist/listening/leveling-ab.wav`(없으면 `oneum-libtool leveled <폴더> --ab <파일>`로 다시 만든다)를 듣거나, 음량 보정을 켜고 여러 앨범을 이어 듣는다. 출력의 음량을 잰 결과는 docs/TESTING.md "보정된 출력의 음량".
   5만 곡 분석은 3분의 1에서 멈췄으므로(문제는 없었음) 끝까지 한 번 돌린다.
8. 새 단축키(⌥⌘→, ⌥⌘←, ⌘⇧.)를 실제 키보드로 눌러 본다.
9. 저장소는 https://github.com/ywjung/oneum 에 올릴 준비가 되어 있다(원격 `github`, 2026-11-15: 작성자 정보 통일, main에 머지, 새 클론에서 빌드·테스트 확인 — docs/RELEASE.md "현재 상태"). `git push -u github main`으로 올린다. 올린 뒤 `.github/workflows/ci.yml`이 실제로 도는지 확인한다(아직 한 번도 실행되지 않음 — Windows 러너에서의 빌드·테스트·실행 확인이 처음 돌게 된다).
10. APE: 검증용 APE 파일(또는 Monkey's Audio 인코더)이 생기면 `ape-decoder`를 붙이고 ffmpeg의 APE 디코더와 샘플 단위로 대조한다.
11. CUE 시트: 리핑 프로그램(EAC·XLD 등)이 만든 실제 "파일 하나짜리" 시트와 이미지가 생기면 앱에 넣어 곡 수·길이·이어 재생을 확인한다(docs/TESTING.md "다섯 번째").

12. iPhone판은 실제 iPhone에 설치되어 실행된다(2026-11-14, `scripts/ios-device.sh`). 기기에서 docs/TESTING.md "iPhone"의 "확인하지 못한 것"을 차례로 본다:
    화면 배치와 터치, 재생, 잠금 화면·제어 센터, 전화 끊김, 이어폰 분리, 파일 넣기, 메모리와 배터리. 그 뒤에 지원 환경으로 적는다. 무료 개인 팀으로 설치한 앱은 7일 뒤 다시 설치해야 한다.
13. iPhone 화면에 없는 것: 출력 장치 선택·곡의 샘플레이트로 출력·독점 출력(USB DAC이 있어야 시도할 수 있음), 키보드 단축키, 목록의 열 고르기, Apple Music 보관함 가져오기, 바깥 폴더를 제자리에서 읽기(docs/IOS_PLAN.md 5단계). 기능을 맞춘 빌드(고정·정렬·선택·순서 바꾸기 등)를 실제 iPhone에 설치해 손가락으로 끄는 조작을 확인한다.
