코드 서명 정책 (Code signing policy)

2026년 11월 23일부터 · Windows용 OnEum의 설치 프로그램과 zip에 적용

지금 릴리스 페이지에 있는 Windows용 파일은 서명되어 있지 않습니다. 오픈 소스 프로젝트의 서명을 맡아 주는 SignPath Foundation에 신청할 예정이고, 받아들여지면 아래대로 서명합니다.

서명하는 곳

신청이 받아들여진 뒤의 Windows 릴리스에는 다음이 적용됩니다.

Free code signing provided by SignPath.io, certificate by SignPath Foundation

그때 파일의 속성 → 디지털 서명에 보이는 게시자는 “SignPath Foundation”입니다. 그 전까지는 서명이 없으므로 Windows SmartScreen이 실행 전에 묻습니다.

무엇에 서명하는가

  • 이 저장소의 소스로 만든 OnEum.exe와 설치 프로그램뿐입니다. 다른 프로젝트의 파일에는 서명하지 않습니다.
  • 서명할 파일은 개발자의 컴퓨터가 아니라 GitHub Actions(GitHub이 운영하는 러너)에서, 공개된 커밋으로부터 빌드합니다. 빌드 방법은 저장소의 워크플로와 패키징 스크립트에 있습니다.
  • 릴리스마다 아래의 승인자가 서명 요청을 직접 확인하고 승인합니다. 자동으로 서명되는 일은 없습니다.

역할

OnEum은 한 사람이 유지하는 프로젝트입니다.

  • 커밋하는 사람과 검토하는 사람 (Committers and reviewers): ywjung (저장소의 소유자). 다른 사람이 보낸 변경(pull request)은 소유자가 검토한 뒤에만 합칩니다.
  • 승인하는 사람 (Approvers): ywjung

개인정보

OnEum은 개인정보를 수집하지 않습니다. 기기에 남는 것과 기기 밖으로 나가는 것은 개인정보 처리방침에 적혀 있습니다.

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

(이 프로그램은 사용자나 설치 · 운영하는 사람이 직접 요청한 경우가 아니면 어떤 정보도 네트워크의 다른 시스템으로 보내지 않습니다.)

파일을 확인하는 방법

  • 릴리스마다 체크섬 파일(SHA256SUMS-windows.txt)을 함께 올립니다. 내려받은 파일의 SHA-256이 거기 적힌 값과 같은지 볼 수 있습니다.
  • 서명된 뒤에는 파일의 속성 → 디지털 서명에서 게시자와 타임스탬프를 볼 수 있습니다.

문제를 알릴 때

파일이나 서명에 이상한 점이 있으면 GitHub의 이슈로 알려 주세요. SignPath Foundation의 인증서로 서명된 파일이 그 재단의 조건을 어긴다고 보이면 재단의 조건에 적힌 대로 재단에 직접 알릴 수도 있습니다.
