Code signing policy

From 24 November 2026 · for the setup program and the zip of OnEum for Windows

The files for Windows on the releases page today are not signed. OnEum applied to SignPath Foundation, which signs for open-source projects, on 24 November 2026 and is waiting for its decision. If the project is accepted, releases are signed as described here.

Who signs

For Windows releases made after the project has been accepted:

Free code signing provided by SignPath.io, certificate by SignPath Foundation

The publisher shown under Properties → Digital Signatures is then “SignPath Foundation”. Until then the files carry no signature, and Windows SmartScreen asks before it runs them.

What is signed

  • Only OnEum.exe and the setup program, built from the source in this repository. Files of other projects are not signed.
  • The files to be signed are built by GitHub Actions on runners that GitHub hosts, from a public commit, and not on a developer’s computer. How they are built is in the repository: the workflow and the packaging script.
  • For every release the approver below looks at the signing request and approves it by hand. Nothing is signed automatically.

Roles

OnEum is maintained by one person.

  • Committers and reviewers: ywjung (the owner of the repository). Changes sent by others (pull requests) are merged only after the owner has reviewed them.
  • Approvers: ywjung

Privacy

OnEum collects no personal data. What stays on the device and what leaves it is written in the privacy policy.

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

Checking a file

  • Every release comes with a file of checksums (SHA256SUMS-windows.txt): the SHA-256 of a downloaded file can be compared with the value written there.
  • Once the files are signed, Properties → Digital Signatures shows the publisher and the time stamp.

Reporting a problem

If something about a file or its signature looks wrong, please open an issue on GitHub. If a file signed with a certificate of SignPath Foundation seems to break the foundation’s conditions, it can also be reported to the foundation, as its conditions describe.

Changes

If this policy changes, this page is changed and the date above with it. Earlier versions can be seen in the repository’s history.
